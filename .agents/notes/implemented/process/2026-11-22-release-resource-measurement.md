# Agent Note: 发布资源门有了可复现的测量

Status: implemented

## Problem

`v1-exe` 的 NFR 里有三条硬预算（体积 ≤15MB、冷启动 <1s、静止工作集 ≤50MB、静止 CPU <1%），但仓库里没有任何测量手段：没有脚本、没有记录、没有基线。预算从写下那天起就没被验证过一次，因此"达标与否"这个问题长期无解——不是没达标，是没人知道。

首轮实测（`target/release/MoeFrame.exe`）：

- 体积 7.48MB ✓
- 14 图库静止 CPU 0.48% ✓；单图库 5.47% ✗
- 冷启动到首张图 2833ms / 5207ms ✗（目标 <1s）
- 静止工作集 151.68MB / 156.66MB ✗（目标 ≤50MB），峰值 227.3MB
- 两条对照：14 张 1080p–4K 与单张 512×512 的工作集、启动耗时都基本不变 → 工作集是进程基线，与图数/图尺寸无关；启动也不由解码决定。

## Decision

- **`scripts/measure-release.ps1`** 是唯一的资源测量入口，三段独立可跑：
  - `-GenerateSamples`：生成两套图库（14 张 1080p–4K、单张 512×512）。
  - 启动+静止：`LaunchMs`（自定义 `[startup]` 标记从进程入口到纹理上传）、`WorkingSetMB`、`PeakWorkingSetMB`、`CpuPercent`。
  - `-SoakMinutes N`：每 3 秒一张的连续轮播，逐秒采样 CSV，看工作集是否随时间单调增长。
  - 一万张图库：验证扫描/轮播在规模下的行为。
- **每次测量用独立临时 `APPDATA`**（`<root>\MoeFrame` 预建好再启动），测完即弃 → 不碰用户真实配置，也让「全新安装是否建目录」这类缺陷自然暴露。
- **产物落 `target/release-measure/<case>/`**（JSON + Markdown + 原始 LOG 副本），不进仓库。
- 产品侧只加**只写日志、不参与行为**的 `[startup]` 标记：`launch`（`main` 入口）、`app-created`（`CreationContext` 内）、`first-frame`（`ui()` 首次进入）、`first-image`（纹理上传）。这是 NFR-4 唯一口径，留给任何后续测量工具复用。
- 归因用**内存探针**而不是逐点写文件：`probe_start/probe_mark/probe_dump` 在 `thread_local` 里记 `Instant`，首帧结束一次性落盘。逐点开合日志文件会把 I/O 混进被测耗时（实测能贡献 1–5s 的假停顿），归因代码用完即删，不进仓库。

## 归因结论（启动）

三次采样的一致结构：**框架初始化 184–190ms → 首帧开头一次 0.96–1.76s 的整段停顿 → 之后每帧 ~50ms（预加载轮询）→ 首张图在 1265–2179ms**。

那次停顿夹在两条相邻语句之间（`core.handle(Intent::Started)` 之后、`dispatch` 的第一个分支之前），中间没有我们自己的工作量，且换成内存探针后依然出现 → 不是产品代码路径的耗时，属于进程外的阻塞（新进程首次被安全软件扫描、或 GL/窗口系统的首次激活）。这条线索决定了 <1s 目标要往哪里查：先排除外部阻塞，再谈优化。

## Alternatives considered

- **在 CI 里跑资源门** — 最强理由：唯一强制的门。否决：需要交互式桌面会话（窗口、托盘、前台焦点），`windows-latest` 的 session 0 跑不了；且启动耗时在共享 runner 上没有可比性。资源门只能本地跑，并把结论写进票。
- **手工开任务管理器看数字** — 否决：不可复现、无原始数据、无法看随时间增长。
- **用 `perfview`/ETW 做首次归因** — 最强理由：能直接看到阻塞来源。否决（暂时）：需要额外工具与符号，先用手写探针把「是不是我们的代码」这个二选一问题答掉，成本更低。
- **把探针留在产品代码里当常驻诊断** — 否决：`thread_local` + 每帧分支是给归因用的，常驻只会变成新的噪声源。

## Consequences

- 三条预算从"没人知道"变成"知道当前差多少"，且差距可复现、可对比；票 22 里已写入首轮数字与归因结论。
- 每次回归测量要独占前台窗口约 40 秒（启动+静止）或 N 分钟（soak），CI 与后台代理都不能跑——资源门是人工/本地门。
- `[startup]` 四个标记成为 NFR-4 的固定口径，测量脚本依赖 `moe_frame.log` 里的事件名，改名会破坏脚本。
- 启动停顿落在进程外，后续任何启动优化都必须先做外部对照，否则会把系统噪声当成本项目的收益。
