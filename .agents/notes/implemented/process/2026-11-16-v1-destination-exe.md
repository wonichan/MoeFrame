# Agent Note: V1 终点是可验收的 release exe

Status: implemented

## Problem

[V1 交接路线](../../../../.scratch/v1-route/map.md) 把终点定成「只锁定路线、不写程序」。按这个终点，写出 `MoeFrame.exe` 在范围外。用户随后要求终点改为一个可运行的程序。

## Decision

活地图是 [V1 可运行程序](../../../../.scratch/v1-exe/map.md)。终点是通过需求文档第 10 节的 release `MoeFrame.exe`，外加简短 README。P1 不挡完成。这张图允许实现。旧图保留原终点文字，只标作废，不改写成反面。

设置窗边界已关闭，按 [ADR-0003](../../../../docs/adr/0003-settings-window-boundary.md) 实现。[边缘缩放先验证](../../../../.scratch/v1-exe/issues/06-resize-before-switch.md) 和 [全分辨率解码](../../../../.scratch/v1-exe/issues/07-full-res-decode.md) 已关闭验证路线的决定，但两项实际验证都尚未执行。先分别做独立最小验证，通过后才进入对应的正式实现；失败先排查，确认仍不能满足要求后再另开备选票，不直接更换 GUI 框架或解码器。

## Execution tickets

用户确认的实施拆分是 16 张纵向切片，在原议题目录从 08 续号到 23；原 01–07 决定票、父规格与路线图保持不动。规格和地图中「本轮不预切」记录的是前次写规格与定路线的范围，不阻止用户本次明确批准的拆票工作。新票使用 `ready-for-agent`，不把旧 wayfinder 票改成该状态。

当前执行前沿只有 [08：窗口最小验证](../../../../.scratch/v1-exe/issues/08-window-validation.md)和 [09：解码与内存最小验证](../../../../.scratch/v1-exe/issues/09-decode-memory-validation.md)，两者互不阻塞。真实操作、测量及阈值确认缺失时，验证票不能完成；后继票只在其直接阻塞票实际完成后开始。其余票逐步打通可演示行为，最终由 [23：端到端验收与最终交付](../../../../.scratch/v1-exe/issues/23-release-acceptance.md)收口，不把全部实现强行串成一条链。

各功能票自带应用行为测试及所需 playlist 先测试后实现，不将配置、UI、测试拆成只能单层验收的横向票。代价是部分能力要在后续切片才补齐；中间版本只展示已生效功能，不用无效控件或编译成功冒充产品完成。

## Testing

[V1 规格](../../../../.scratch/v1-exe/spec.md) 汇总本图的完成线、ADR 覆盖关系与未完成门禁。规格的 `ready-for-agent` 仅表示可从独立最小验证开始执行，不改变地图子票状态，也不表示验证已通过。

用户确认的自动化主接缝是应用行为入口，另保留第 10 节明确要求的 playlist 核心单测。这样能验证导航、计时、恢复和设置提交的组合行为，不把测试绑在私有实现上；代价是窗口、托盘、自启、DPI 和资源指标仍需真实 Windows 验收，不能由 mock 或编译结果替代。仓库现有应用代码和自动化仅限 [08 独立窗口验证](../testing/2026-11-17-window-validation-harness.md)，不包含正式相框实现；人工实机验收仍未完成。

票据发布检查覆盖 16 个独立文件、08–23 连续编号、状态、验收复选项、本地引用、直接阻塞关系、无环与无重复阻塞边，以及前沿恰为 08 和 09；同时比较父规格、地图与旧七票的内容指纹，确保发布没有改动它们。这些检查只证明票据结构与范围记录，不证明程序或实机验收已完成。

## Alternatives considered

- **改旧图终点，把实现捡回来** — 旧图已经把写程序划到范围外。直接改终点会把划出的工作在同一张图上复活。否掉，改画终点后另开图。
- **终点停在能弹出的骨架** — 这样最快能看到窗口。否掉，因为用户接受的完成线是第 10 节，不是 debug 骨架。

- **实施票从 01 另起一组或重编旧票** — 便于让新任务单独从头编号，但会分散同一特性的规格归属，或破坏已有引用。使用用户确认的原目录 08–23 续号，保留旧票身份。
- **按配置、图片加载、UI、测试分层拆票** — 职责分工直观，但单票无法展示用户可用的闭环。按用户行为纵向切片，各票包含自己的测试，仅保留两项独立验证作为正式实现门禁。

## Consequences

- **收益**：完成线与第 10 节和 release 交付物一致，后续会话不会停在「只写决定」。
- **代价与已知上限**：设置窗边界不再挡住那一块实现。无边框窗口与解码路线虽已确定，但正式实现仍须等待各自的最小验证通过；解码瞬时峰值上限与 Limits 阈值还须实测后由用户确认。P1 仍不在本图里；若要 P1 进完成线，必须再改终点。
