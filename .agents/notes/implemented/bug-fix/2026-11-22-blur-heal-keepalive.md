# Agent Note: 失焦切换模糊——治愈保活修复

Status: implemented

## Problem

失去焦点时，偶现定时切换后的插图模糊；点击选中程序后立即恢复
清晰（用户 2026-11-22 报告，附截图）。

## Decision

诊断（diagnosing-bugs 流程，管线级模拟复现）：导航解码口径在
`begin_load` 时快照为旧窗口物理尺寸，切到更宽的图后窗口随比例
变宽，纹理相对新窗口偏小，放大显示即糊——纠正靠管线 `tick` 的
治愈刷新；但刷新有 0.25s 停稳门，计时走 egui 帧时间，而切换
完成后帧尾调度直接睡到下一次轮播截止、不再出帧，停稳永远走不
完，聚焦产生新帧才瞬间治愈。「偶现」源于只有切到更宽比例时
纹理才小于显示面积。

修复只动宿主调度，不动管线与解码口径：

- `texture.rs::refresh_display_data`：tick 后若当前口径仍过期、
  本帧未发出刷新、且过期目标是新出现的变化，给帧尾设 2s 保活
  截止（`heal_repaint_until_ms`），并记下已设目标
  （`stale_target_seen`，同一目标只设一次——刷新失败被管线按
  期望键抑制后不再续，保活自然到期，不无限出帧）。
- `frame_ui.rs`：帧尾唤醒裁决抽为纯函数 `next_frame_delay`
  （隐藏心跳 250ms → 加载轮询 50ms → 治愈保活 50ms → 睡到
  轮播截止），保活分支插在加载轮询与轮播截止之间。

## Alternatives considered

- 免除转正后刷新的停稳门：停稳门防的是拖动缩放反复解码，转正
  后与拖动在 tick 看来同形，放行会把防抖一并拆掉，不取。
- 导航解码直接按切换后的窗口尺寸解码：切换后尺寸要等解码出
  源图比例才知道，鸡生蛋；且动摇 DisplayKey 口径语义，不取。
- 提高轮播期常驻帧率：全局代价（违背低占用定位），不取。

## Testing

- 管线级模拟（临时测试，未入库）：喂入失焦切换的帧序列，证实
  转正后稀疏帧内无刷新发出、迟到的焦点帧才触发——与症状吻合。
- `next_frame_delay` 五个回归测试钉住分支优先级与边界（宿主
  测试，Windows 目标编译通过；执行在 CI / 真机）。
- Windows 目标 clippy（-D warnings）干净；库全量测试 231/231
  （含上述模拟 1 条）通过。
- 未验证：真机复测（失焦等自动切换到更宽的图）留工单。

## Consequences

- 每次口径变化后最多多出 2s 的 50ms 帧（约 40 帧），之后恢复
  睡眠调度；常驻占用不变。
- 与搁置的「原生 resize 偶现异常」可能相邻：resize 迟到时保活
  帧给它 2s 落地窗口；仍不落地维持原行为，不在本票处理。
- 本票按用户要求以 PR 形式提交，不直接合入 main。
