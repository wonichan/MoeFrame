# Agent Note: 原生缩放结束后再执行到期轮播

Status: implemented

## Problem

官方 `v0.1.3` 在 Windows 原生拖角时可以切到宽图，但几何机为避免和鼠标争抢，不会立即调宽。无动画绘制把完整宽图压进旧比例的窗口。松手后，尺寸命令也不是实际视口已到位的确认；仅推迟到松手，仍可能先画出压扁的新图。

## Decision

- 仅在可见相框原生缩放时暂缓发起自动切换，不改播放开关、截止时刻或间隔；松手处理一次已到期的切换，按既有规则从成功显示时重计。移动、手动切换、已开始的动画和隐藏相框轮播沿用原规则。
- 已发出的自动加载完成后，宿主暂存同一传入槽的显示数据，不上传或提交。可以切换时仍由几何机推导尺寸；有新尺寸命令时，等 UI 观察到对应尺寸再上传并提交或开播动画。换图库丢弃待显示图，撤销未提交比例。刷新失败策略不变。
- 自定义/内置画框继续用各自已有的几何推导，不在轮播逻辑里复制尺寸计算。系统没有确认尺寸时，250 ms 后回到既有显示路径，不能卡住轮播。

## Alternatives considered

- 缩放期间照常切，等比居中显示：保持轮播时序很直接，但宽竖互切会明显露底；用户选择在松手前保留当前图。
- 切图时强制改窗口尺寸：图和窗口可以同时追目标比例，但会和 Windows 原生手势争抢，不采用。
- 松手即转正纹理，不等待视口：实现较少，但 Windows 复测确实观察到松手后旧尺寸先呈现宽图，不能解决闪动。

## Consequences

- 轮播至多等到当前缩放结束，并在收到新尺寸观察后继续；长时间按住不积攒多次切换。这个等待不往 `display_data` 增加第三槽，也不改后台解码协议。
- 原生手势期间按低频帧确认物理松手，避免已到期的轮播在按住时忙循环，也不依赖 egui 一定收到松手事件。系统拒绝改尺寸时的超时保底不承诺首帧贴边。

## Testing

- 播放时序用 `tests/app_core.rs` 钉住；Windows 帧采样与实机证据见[补测 W1c](../../../../real-machine-check-closeout.md)。
- [显示数据管线](../feature/2026-11-21-display-data-pipeline.md)继续持有两槽记账；[几何与切换动画收编笔记](../feature/2026-11-23-crossfade-merge.md)中的不抢手势、瞬时尺寸和原生回弹修复仍有效。
