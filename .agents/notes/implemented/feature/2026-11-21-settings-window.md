# Agent Note: 设置窗是宿主的第二个视口，不是核心的第二份状态

Status: implemented

## Problem

[工单 18](../../../../.scratch/v1-exe/issues/18-settings-window.md) 要一块独立设置窗：相框菜单与托盘打开同一块、已开带到前台、无确定/取消，播放模式、六档间隔、适应/填充点选即刻生效落盘。难点不在控件，而在状态归属：设置若在窗里自存一份，菜单与实际行为就会分叉；填充若只改绘制，纹理还是适应尺寸的显示数据（一边小于窗口），放大填充必然发糊——填充的显示数据必须按物理窗口的覆盖尺寸重新生成。另外这票之前，适应/填充只在启动时从配置读一次，没有任何运行时入口，相框菜单里也没有显示方式项（父规格 §6 的菜单面缺这一项，是工单 10 以来的存量缺口）。

## Decision

- 设置窗是宿主层的 egui 即时视口（`show_viewport_immediate`，全程一个固定 ViewportId）：`settings_open` 一个布尔就是全部生命周期状态。打开请求（相框菜单「设置」或托盘「设置」）已开时只发 Focus 命令，不重置位置、不重建；打开时按相框视口的 monitor_size 算一次居中位置（只在打开那一帧带 position），位置不落盘、不随相框移动。窗内关闭请求（标题栏按钮/Alt+F4）与 Esc 只置关闭标记，不派发任何核心意图——关设置窗与相框的关闭/隐藏/播放完全无关；相框隐藏时从托盘开设置窗不发任何显示相框的命令。
- 控件只有已打通的三组（ADR-0003）：播放模式与六档间隔的点选直接派发既有核心意图 PlaybackModeSelected/IntervalSelected——与相框菜单同一入口，计时规则（模式不重置计时、间隔同值不重计、暂停中只记值）自动一致，菜单与设置窗都每帧现读核心状态，不存在第二份配置状态。间隔对不上任何预设时（配置里的自定义值）六档全不勾选，与决定 03 一致。
- 显示方式是宿主呈现状态：新增 `ConfigStore::set_fit_mode` 走既有字段级 update() 落盘；宿主 `apply_fit_mode`（设置窗与新补的相框菜单「显示方式」子菜单共用）改状态+落盘+触发当前图重载。绘制几何抽到库 `display::display_size`（适应=min 比例完整放入、填充=max 比例覆盖），宿主与测试共用一份；面板裁剪即居中裁剪，不支持 Stretch。
- 填充的显示数据靠重载保证：宿主记 `texture_mode`（当前纹理按哪种方式生成）与 `load_mode`（在飞核心加载用的方式，转正时记入前者）；两者与生效方式不一致且不在转场/重载中时，`refresh_texture_mode` 以哨兵序号 RELOAD_SEQ 向工作线程重载当前图，回送只换纹理——不经核心、不算显示、不进历史/进度、不动计时。在飞竞态靠回送前的四重校验（待重载记录在、非转场中、核心当前图未变、路径一致）丢弃过期结果；连点两次切换靠每帧 refresh 自行收敛。解码缝本身早已按模式算目标尺寸（Fit 放入、Fill 覆盖，工单 09），本票未动。

## Alternatives considered

- **填充只改绘制、不重载** — 省掉整套纹理模式追踪；但适应数据一边小于窗口，填充放大必糊，违反工单「按物理窗口的覆盖尺寸生成显示数据」，拒绝。
- **显示方式进核心当意图** — 核心是播放行为层，显示方式不影响任何播放规则，进核心会让行为测试面背上呈现细节；宿主状态+落盘已满足「同一份已保存状态」，拒绝。
- **设置窗用延迟视口（show_viewport_deferred）** — 帧循环更省；但回调是 'static 闭包，读写应用状态要另搭共享结构，即时视口的 FnMut 直接借用宿主、代码简单得多；设置窗打开期间父视口多跟随重绘，成本可忽略，拒绝延迟式。

## Testing

- 全量测试 153 项全绿（本票新增 7 项）：tests/display.rs 六项验 display_size——适应横图留上下黑边、竖图留左右黑边，填充横图纵向满/横向溢出、竖图横向满/纵向溢出，比例恰合时两模式一致，退化尺寸不除零；tests/config.rs 一项验 set_fit_mode 真实文件往返且不伤其他字段。模式/间隔的即时生效与计时规则由工单 11/12 的既有核心测试守（同一意图入口），未重复造测试。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。
- 双轴审查（基线 `8520610`）：Standards 轴 1 个硬违规——set_fit_mode 插入时把 set_playback_mode 的文档注释错位到新函数头上，已修复归位；判断项处置：间隔六档预设表抽成宿主常量 INTERVAL_PRESETS（菜单与设置窗共用）、config 里改用已导入的 DisplayMode 短名、绘制处旧注释合并、设置窗尺寸抽常量；哨兵序号方案记为气味但保留（回送变体化要动工作线程协议，收益不抵）。Spec 轴无蔓延、无伪验证，核心机制（单窗、关闭独立、隐藏时托盘开设置、重载竞态、计时规则、P1 不生效）全部核对成立；两处存量部分项如实保留：其一，居中只在单屏精确——egui 只给相框所在屏的尺寸、给不出原点与主屏信息，多屏时按该屏左上角近似、隐藏且拿不到尺寸时回落系统默认位置；其二，相框菜单原缺「显示方式」项（§6），本票已顺带补齐（与设置窗共用 apply_fit_mode），菜单同步自此双向成立。Spec 还点名填充+滑动的起始帧露图：原整宽平移下 640 宽的填充图在 480 窗口起始帧先露出约 80px，已改按各自矩形算行程（切入图从恰好整幅出框处进、切出图走到恰好出框），适应模式的行程随之略短于整宽、两图间距更小，属同一修复的正向变化。
- 未验证：设置窗实际打开/聚焦/居中位置、Esc 与 Alt+F4 只关设置窗、隐藏时托盘开设置不唤出相框、填充的实际观感与滑动衔接——工单验收标准 9 明确要求实机记录，已并入合并实机清单（工单 10–18），本票因此转 `needs-info`，不标 resolved。

## Consequences

- 工单 19 在同一设置窗里加路径框与秒数框：草稿状态归设置窗宿主层，提交（失焦/回车）才派发意图；秒数框与预设共用核心的间隔状态，不要另存一份。工单 20 的几何控件、工单 21 的自启开关同样只加控件、不加状态。
- 隐藏心跳（工单 17）保证隐藏时设置窗的打开请求能被及时处理；设置窗打开期间若相框隐藏，设置改动照常经核心意图生效于隐藏轮播，这是预期行为不是缺陷。
- 居中近似要等 egui 提供多屏原点信息或改走 Win32 才可能精确；实机清单在单屏环境验收即可，多屏用户反馈再议。
- 后续显示策略见 [相框按当前图像比例自适应宽度](2026-11-22-image-driven-frame.md)：Fit/Fill 已不再是设置窗控件；本笔记保留当时的决策理由。
