# Agent Note: 窗口几何全走「观察—停稳—生效」，锁定修正与尺寸重载都不在拖动中抢方向盘

Status: implemented

## Problem

[工单 20](../../../../.scratch/v1-exe/issues/20-window-geometry-dpi.md) 补齐正式窗口的几何闭环：位置/尺寸跨启动恢复并保存、设置窗的宽高比锁定（打开那一刻捕获比例）与恢复默认位置大小、拔掉副屏后相框不丢、DPI 或物理尺寸变化后显示数据按实际像素重做。此前宿主只在启动时读存档几何，从不写回——用户摆好的位置重启即失。难点都在时序与平台边界：OS 模态拖动/缩放期间应用插不上手；egui 不枚举屏幕，只有相框所在屏的 monitor_size；逐帧写盘或逐帧重载都会在拖动中抖动。

## Decision

- 几何落盘走防抖：宿主每帧观察 outer_rect（位置）与 inner_rect（逻辑尺寸），与最近落盘值不同则记候选，停稳 0.6 秒才经 ConfigStore::set_window_geometry 写一次；隐藏时不落盘。恢复默认是显式动作，不走防抖——立即下发 480×320 + 当前屏右下角内缩 24px、立即落盘、锁定开启时锁定比例同步改默认比例；相框隐藏时按同一显示器口径放置并经核心 ToggleVisibilityRequested 显示（与「托盘开设置不唤出相框」相区别，区别在动作来源）。设置窗位置照旧不保存。
- 宽高比锁定：开关落盘在 config 的 lock_aspect，比例本身不落盘——启动时由存档尺寸推导，运行时打开开关那一刻以当前内尺寸捕获。锁定不进相框菜单（决定 03）。修正时机与算法分开：算法是库纯函数 aspect_locked_size（以刚变化的一边为准推导另一边、两边都变以宽为准、套 120 最小边、一边触底按比例反推、双触底最小边优先）；宿主只在「指针未按下且尺寸刚变化」时下发一次 InnerSize，拖动/缩放进行中不抢，停稳后修正。边缘缩放不触发内容手势沿用既有分界（缩放按下不进核心）。
- 启动离屏钳制：首帧拿到 outer_rect 与 monitor_size 后只查一次，库纯函数 offscreen_position 判定「与主屏完全无交集」才钳回主屏右下角内缩 24px，部分可见不动。egui 不枚举屏幕，副屏上的合法位置若完全落在主屏之外会被误钳——这是当前 API 下的已知边界，写在函数文档与工单评论里，不假装多屏完备；钳制后的正确位置会经防抖落盘覆盖旧存档，不会每次启动重复钳。
- 显示数据按物理尺寸重做：工单 18 的哨兵重载一般化为 refresh_display_data——当前纹理的 (模式, 目标物理尺寸) 与生效值任一不一致即重载当前图（只换纹理、不经核心）；texture_target/load_target 跟踪每次数据的生成口径，转正点统一记账。目标尺寸变化（拖动缩放、跨屏 DPI 变化都经 physical_target 汇合）要停稳 250ms 才触发，避免拖动中反复解码；在飞的核心加载若已按新模式/新目标发出则跳过，等其转正刷新记录。旧纹理随替换释放，不留全分辨率或跨尺寸缓存（工作线程缓存键含目标尺寸，旧条目只是未命中，不驻留显示数据）。

## Alternatives considered

- **锁定靠 winit/eframe 原生宽高比约束** — eframe 0.37 的 ViewportBuilder 没有宽高比约束 API，自己在 OS 模态回路里拦截更不可控，拒绝；停稳后修正是当前栈内唯一诚实的做法，代价是拖动过程中比例可暂时失配，实机清单点名验手感。
- **几何变化即时写盘** — 拖动一帧多次写 TOML，既抖又可能写下中间态；0.6 秒防抖写最终态足够，进程被强杀最多丢最后一次移动，拒绝即时写。
- **DPI 变化单独监听** — 物理目标 = 逻辑尺寸 × pixels_per_point，DPI 变化与尺寸变化在 physical_target 处汇合，一条重载路径全覆盖，拒绝分叉。

## Testing

- 全量测试 170 项全绿（本票新增 9 项）：tests/window_geom.rs 七项验锁定修正（宽驱动、高驱动、角拖以宽为准、最小边触底反推含竖长比例、无效比例直通）与离屏钳制（完全离屏回右下、部分可见不动）；tests/config.rs 两项：set_window_geometry/set_lock_aspect 经真实文件的往返、清位置只删 x/y、不伤其他字段；window 坏字段（x 非数字、width 负、height 0、lock_aspect 非布尔）按契约逐字段修复且不伤图库字段。工单标准 9 要求不绑定私有几何函数——两个纯函数是库的公开面，配置走真实文件读写，与既有接缝口径一致。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。
- 双轴审查（基线 `206bcbb`）：Standards 两处硬违规均已修——新 setter 插入时把 set_playback_mode 的文档注释错位（与工单 18 同型错误，已归位）、注释两处用了词汇表 Avoid 词「锁定比例」（已改「锁定宽高比」）；判断项全采纳：两纯函数移入新模块 window_geom、最小边提为 MIN_WINDOW_SIDE 常量、默认尺寸提为 DEFAULT_FRAME_SIZE、右下角公式抽 bottom_right_position 三处共用、两套防抖收敛为 Debounce 结构。Spec 无缺失无蔓延，四处部分项处置：退出冲刷最后几何已补（观察值在 Effect::Exit 派发时落盘，防抖不再丢尾位）；锁定修正的口径在工单里如实记为「停稳后修正」而非拖动中保持；恢复默认/隐藏显示的显示器口径（只有尺寸、无原点，None 时不设位置）如实记录；标准 9 的宿主覆盖缺口（比例捕获、恢复默认、隐藏显示在 Windows 宿主内无自动化）连同新补的 window 修复测试一起如实勾注。
- 未验证：四边四角锁定手感（含 OS 模态缩放期间指针状态冻结的影响）、恢复默认的实际落位、隐藏时恢复默认唤出、拔副屏钳制、多屏与跨 DPI 的实际路径——工单验收标准 10 明确要求实机记录执行人/系统/屏幕/DPI/物理尺寸，未具备的环境保持未验证。已并入合并实机清单（工单 10–20），本票因此转 `needs-info`，不标 resolved。

## Consequences

- 工单 21（开机自启）与 22/23（发布门）不碰几何；但发布实机验收要带上本票的清单节（锁定手感与多屏/DPI 路径）。
- 锁定修正是「停稳后追认」而非「拖动中约束」：任何未来想让拖动过程也保持比例的尝试，都要先解决 OS 模态回路内 egui 无帧的问题，不要在本机制上叠补丁。
- **副屏摆放不保存（明确行为警告）**：offscreen_position 只能按主屏 (0,0) 原点判定，整窗摆在副屏上会在下次启动被移回主屏右下角。这不是未覆盖而是主动取舍（防拔屏丢窗优先），文档注释已按此口径改写；若日后要真多屏，需先有能枚举屏幕与原点的窗口层信息，再改判定，不要在本函数上加猜测性豁免。
- saved_geom 的口径是「最近落盘值」：手改 config 的窗口字段后不重启就拖动相框，防抖会以实际窗口几何覆盖手改值——这是「所见即所存」的预期行为，与不监听配置文件的既定规则一致。
- 后续几何策略见 [相框按当前图像比例自适应宽度](2026-11-22-image-driven-frame.md)：手动宽高比锁定被源图比例驱动的窗口宽度取代；其余观察、防抖和多屏边界仍按本笔记执行。
- 后续切图动画与中心稳定见 [切图交叉淡化与窗口几何动画](2026-11-22-switch-animation-and-geometry.md)：位置改为名义中心锚定，边界细化到 Win32 工作区 6px；停稳落盘与启动离屏钳制不变。
