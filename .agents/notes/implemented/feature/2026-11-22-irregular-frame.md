# Agent Note: V2 异形相框——绘制计划钉死透明口径与空状态描影

Status: implemented

## Problem

工单 03 按矩形外轮廓验收：外轮廓不规则的异形相框是否真的透出
桌面、透明处能不能拖、阴影会不会漏进自定义模式、空状态时洞里
是什么样，都没有逐项钉死。更深一层的问题是宿主每帧的绘制分支
是手拼条件（外观模式 × 相框图状态 × 面板填充），这些约束只活
在条件表达式里，没有测试守着——下一次改绘制的人拼错一个条件，
异形就会悄悄变成假镂空或带上阴影。

## Decision

- 先审计、后动手：异形的机制层在工单 01–03 落地时已齐备——
  窗口永远透明创建（01）；九宫格只画八区、从不覆画相框图的
  透明像素，自定义生效时面板不铺不透明底（03）；自绘软阴影
  只存在于内置画框的绘制函数内，自定义生效路径不经过它；
  指针命中只看窗口矩形（整窗内部是拖动区、8px 缩放带按包围
  盒矩形计算），与画了什么无关，透明处因此天然可拖、不穿透。
  本票不新造任何机制。
- 新增库层绘制计划 `frame_layout::paint_plan`：输入（外观
  模式 × 相框图是否生效 × 是否有图），输出一帧的裁决——面板
  是否铺不透明底、画框层三选一（无 / 内置三层 / 九宫格相框
  图）、空状态提示的落点。宿主 `frame_ui` 改为照计划绘制，
  原手拼条件删除。计划表把异形约束钉成可测的事实：自定义
  生效时画框层只有九宫格（阴影无从混入）、面板必透明；自
  定义未生效（未选图或分析回退）即回退内置，口径与内置模式
  逐项一致；极简维持面板黑底、无画框层。
- 空状态补一条边：自定义生效且无图时，相框图照常绘制、洞
  保持透明，提示文字浮在洞中央并先衬一层深色描影再落浅字
  ——背景是透出的桌面、明暗未知，不衬影在浅色桌面上会看
  不清。极简的提示背景是自家黑底，不加描影；内置的提示由
  其绘制内部按卡纸在场与否选字色，两者都不变。
- 顺手修正两处随工单推进过期的注释：`AppearanceMode::insets`
  的自定义口径说明、透明创建注释里「异形（二期工单 04）预留」
  的旧说法。

## Testing

- 布局接缝（tests/frame_layout.rs 新增 5 例）：内置 / 自定义
  生效 / 自定义回退 / 极简四种计划逐项断言（画框层、面板铺
  底），外加空状态提示落点矩阵（有图不画、自定义浮排带描影、
  极简浮排无描影、内置与回退走绘制内部）。
- 本机验证：Linux 刮擦副本全套 281 例全过（基线 276 + 本票
  新增 5）；Windows 目标 `cargo check --all-targets` 与
  `clippy -D warnings` 干净，`cargo fmt --check` 通过。异形
  上屏观感、透明处拖动与缩放的手感、空状态提示在真实桌面
  上的可读性只能在用户 Windows 机上核，工单 04 因此停在
  needs-info。

## Alternatives considered

- 只审计不抽计划函数，异形行为全靠真机清单守：省事，但
  「阴影不进自定义」「面板不铺底」继续只活在宿主条件里，
  本票审计出的最大风险正是分支拼错；计划函数把风险收进
  一张可测的纯函数小表，成本远低于一次真机返工。
- 给透明区域做按像素命中穿透：spec 明确本期不做（透明处
  等同框体可拖动），是二期候选，不在本票范围。

## Consequences

- 收益：异形行为由计划表 + 布局测试双重钉死，宿主绘制收敛
  为照单执行；自定义空状态在任意明暗的桌面上都可读。
- 代价与遗留：多一个计划类型要随外观模式演进同步维护（新
  增模式时计划函数与测试要一起改）。真机轮欠：异形相框图
  上屏观感、透明处拖动/缩放手感、空状态描影的实际效果。
  点击穿透与异形轮廓软阴影仍是二期候选。
