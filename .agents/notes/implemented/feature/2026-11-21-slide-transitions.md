# Agent Note: 滑动转场把「成功显示」的提交点从加载完成挪到动画完成

Status: implemented

## Problem

[工单 14](../../../../.scratch/v1-exe/issues/14-slide-transitions.md) 要给前后切换加约 300ms、ease-out、方向正确的滑动动画，并满足父规格 §5 的三条硬约束：动画期间只保留最后一个新切换意图、不并行开启第二段；目标未就绪时保持当前图不闪白；「成功显示才提交状态」（ADR-0002）——本轮进度、历史与跨启动落盘只能在图片真正显示后记账。若提交仍发生在加载完成时，转场期间退出会把一张从未真正显示的图记成当前图；若动画状态只放在宿主渲染层，行为核心就无法用可控时间与加载结果测试方向、连点合并与暂停语义（父规格 Testing Decisions）。

## Decision

- 提交点后移：导航加载成功后，行为核心只发 `StartTransition{from, to, direction}` 并进入转场状态，视图仍停在源图；宿主渲染约 300ms 滑动（`SLIDE_SECONDS = 0.3`，三次 ease-out），到时回送 `TransitionCompleted`，核心此刻才经 `commit_display` 统一提交——记账、预加载、`SaveResumeState` 落盘、从完成时刻计满间隔，都只发生在这一步。首图加载没有源图可滑出，直接提交，不走转场。
- 方向由导航意图在产生候选时定死，随在飞加载一路带到转场效果：Next 时目标从右向左进入，Prev 相反；自动轮播即 Next。不由目标排序或加载完成顺序决定（验收标准 2）。
- 转场期间与加载期间共用同一条「只留最后一个手动意图」队列：`navigate` 在 pending 或 transition 在飞时都只登记最后一个方向，自动意图不登记；Tick 在转场期间整体挂起，间隔截止点在提交时重设，因此动画不是第二份计时器。宿主侧无转场的回送（重扫取消渲染等）被核心忽略。
- 落位方式收敛为单一 `Landing` 类型（新鲜/回看/返回/恢复），导航产生候选时定下，转场与提交沿用同一份，不再有平行的导航类型与转换函数（Standards 审查后合并）。
- 历史落位的兜底：转场期间切换播放模式会清历史游标，向前返回的提交可能落空；此时退到 `land_restored` 只落位不记账，绝不把已经成功显示的图清成无图状态（Spec 审查发现的真实缺陷，已加回归测试）。
- 宿主纹理生命周期：新图先上传为 `incoming`；起转场则与源图纹理同绘滑动，完成时源图 handle 随替换释放、目标图转正；未起转场（首图/直接提交）则立即转正。新一轮扫描取消进行中的转场并丢弃 incoming，画面回到核心仍在显示的源图。

## Alternatives considered

- **动画只做在宿主渲染层、核心维持加载完成即提交** — 改动最小；但转场期间退出会落盘未真正显示的图，且方向/连点/暂停语义无法在行为接缝测试，违反工单验收标准 8，因此拒绝。
- **核心按 Tick 推进动画进度、到截止点自动提交** — 宿主更薄；但核心要为渲染帧率持续收 Tick，且宿主渲染时钟与核心逻辑时钟会出现双轨，`TransitionCompleted` 回送是更符合既有「效果—回送」模式的单向契约，因此拒绝。
- **转场期间排队意图逐个执行** — 连点几下播几段看似跟手；但父规格 §5 与故事 49 明确只保留最后一个，因此拒绝。

## Testing

- 全量测试 120 项全绿（本票新增 6 项行为测试）：上下张转场方向与「完成时才提交」（转场中视图不变、无落盘、Tick 过旧截止点也不触发，完成后从完成时计满间隔）；转场中连续相反意图只执行最后一个；转场中暂停仍提交显示但不计时；无转场的完成回送被忽略；转场期间切模式不清空画面（回归）；转场后导航全失败保留新图。既有 8 项导航链测试改为经 `settle_transition` 结算转场后继续断言，语义不变。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。
- 双轴审查（基线 `eaae43b`）：Spec 轴一项真实缺陷已修正——转场期间切换播放模式清游标可致向前返回提交落空、画面被清成无图，现退到只落位不记账并加回归测试；另指出慢图/失败对转场路径的覆盖部分依赖工单 11/12 的既有测试，已补「转场后失败保留新图」一项。Standards 轴无硬违规；判断项处置：`NavKind`/`Landing` 双类型合并为一，宿主改为按 dispatch 后的 slide 状态决定纹理转正（不再扫描效果列表）；实机清单文件从本票提交中拆出、单独提交。
- 未验证：真实窗口中的滑动观感、方向、无白屏与连点手感、动画中拖动——本票验收标准 9 本就要求实机演示，已并入仓库根目录的合并实机清单（工单 10–14），本票因此转 `needs-info`，不标 resolved。

## Consequences

- 此后任何「显示一张新图」的路径都必须回答「有没有源图可滑出」：工单 16 的手动重新扫描若要在图库变化后切换显示，应沿用首图直接提交或显式开启转场的二分，不要绕开 `commit_display` 另行记账。
- 工单 15（手势）接入时注意：动画期间的导航意图已经进入核心的只留最后规则，侧边单击/双击判定产出的意图直接走现有入口即可；双击打开的「当前图」以核心视图为准，转场期间仍是源图（父规格 §4 已定）。
- 宿主的转场时钟是 egui UI 时钟（秒），核心只认回送事件不认时长；两者若不一致（宿主改时长常量），行为语义不变，只是观感时长变化——`SLIDE_SECONDS` 是唯一的时长定义处。
- 后续显示策略见 [相框按当前图像比例自适应宽度](2026-11-22-image-driven-frame.md)：滑动动画已关闭，成功显示提交仍由核心完成回执维持。
