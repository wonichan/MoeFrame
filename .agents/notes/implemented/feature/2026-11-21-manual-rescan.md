# Agent Note: 手动重扫是播放序列的一次合并，不是重新开始

Status: implemented

## Problem

[工单 16](../../../../.scratch/v1-exe/issues/16-manual-rescan.md) 要让用户增删收藏文件夹里的图片后，点一次菜单「重新扫描」就能看到新增、避开已删，同时不打断仍有效的当前图、不丢失本轮进度与历史。此前扫描回送只有一条路：整表重建播放序列走首图/恢复流程——那是为启动与换文件夹设计的，直接拿来做重扫会把当前轮清零重来。父规格 §3 对图库变化另有明确规则：删除路径从本轮进度及后续播放剔除、新增路径作为本轮未看、仍有未看旧路径时不整轮重洗、当前图缺失时按模式规则处理。

## Decision

- 核心新增 `Intent::RescanRequested` 与在飞扫描标记 `scan: Option<ScanKind>`（Initial/Rescan）：重扫只对当前已生效文件夹发 `Effect::Scan`；扫描或加载在飞时不重复发起（加载在飞时重扫会冲掉在飞状态，且首图未落定前缺失路径的身份已被恢复流程消费，顺序后继定位会落空）。扫描回送按种类分流：Initial 走原有首图/恢复流程，Rescan 走合并分支。
- 合并落在 `Playlist::rescan`：本轮进度与洗牌袋只保留仍在图库的路径（成员判断走 HashSet，大图库不逐项线性扫）；已备好的下一轮袋在图库变化后作废；新增未看路径随机插入袋中，已有顺序不重洗（有专门的相对顺序不变量测试守住，不只断言集合）；历史原样保留，回看时跳过缺失路径；当前图以路径判断存废（内部存下标，换表后重新定位）。随机模式当前图缺失时在合并内清空本轮进度。
- 核心重扫分支：当前图存活 → 不重新加载、不动轮播截止时刻，只刷新预加载目标并以 `SaveResumeState` 落盘合并后的当前图/进度/历史；当前图缺失 → 与工单 13 恢复共用抽出的 `candidates_when_current_missing`（顺序从自然序后继起循环、随机从洗牌袋），替代图经既有 Initial 加载路径成功显示后才提交；图库为空 → 回无图状态并新增 `Effect::ClearResumeState`（宿主以 `save_resume_state(None, &[], &[])` 落盘），同一处理也补到启动/恢复的两处空扫描返回——否则内存里已剔除的路径会因落盘残留而在重启后复活。
- 宿主只加两处：菜单「重新扫描」项（与其他菜单项同一套意图转发），以及扫描回送后核心为无图状态时同步清纹理（重扫清空图库时画面不能留着已删的图）。

## Alternatives considered

- **重扫走原有整表重建 + 把当前图当恢复图** — 复用最多；但本轮进度、洗牌袋顺序与历史游标都会被重建语义污染（恢复是「跨启动」语义，重扫是「同轮继续」），且随机模式的防重复例外会被误用，因此拒绝，合并必须是播放序列自己的操作。
- **文件监听/定时重扫自动合并** — 工单与父规格明确排除（不实现自动热更新），且监听句柄与防抖会给这个小工具加上不成比例的常驻复杂度，因此拒绝，只做手动触发。
- **空图库时不落盘、靠下次启动的恢复过滤兜底** — 恢复确实会按图库过滤进度，但当前图若恰被用户重新放回磁盘就会「复活」成恢复图，与准则 6「不恢复已剔除的路径状态」冲突，因此拒绝，空状态显式清落盘。

## Testing

- 全量测试 142 项全绿（本票新增 12 项）：播放序列合并单元测试覆盖删除剔除、新增并入本轮、剩余未看相对顺序不变、随机当前缺失清进度、顺序当前缺失保留进度、历史保留且回看跳过已删、空图库；行为测试覆盖存活不打断且落盘合并状态、随机缺失开新轮、顺序缺失去后继、清空图库产出 ClearResumeState、加载在飞时重扫被忽略、在飞重扫不重复发起。
- 真实临时目录全流程测试（tests/rescan_flow.rs）：在临时目录真实创建 a/b/c 三个文件，真实扫描、导航落盘后，在磁盘上删 c 增 d，手动重扫，断言当前图不打断且落盘的当前图/进度/历史为合并后状态；随后用同一配置文件重建核心模拟重启，断言首图仍恢复为 b 且下一张候选为 [d, a]（c 不复活、d 已在列）。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。
- 双轴审查（基线 `3ed4a0a`）：Standards 轴无硬违规，判断项全部采纳——缺失当前图候选规则抽为共用函数（恢复与重扫不再各一份）、重扫成员判断改集合、两个扫描布尔合并为 `Option<ScanKind>`、新 expect 信息与文件既有英文惯例对齐。Spec 轴无合并语义缺陷、无范围蔓延；指出三处覆盖/一致性缺口并已补齐——真实临时目录测试缺失（已新增 rescan_flow）、重扫至空图库不落盘（已加 ClearResumeState 并推广到全部空扫描路径）、「不整轮重洗」只有集合断言（已加相对顺序不变量测试）；其点出的低严重度边界（首图未落定前重扫使顺序后继定位落空）以「加载在飞时不发起重扫」从源头关闭。

## Consequences

- 工单 19 的设置窗「重新扫描」按钮直接发同一个 `Intent::RescanRequested` 即可接入同一生效图库行为，不需要第二套合并逻辑；设置窗打开期间若有加载在飞，重扫会被核心忽略，按钮反馈需按「无效果返回即未执行」处理。
- `Effect::ClearResumeState` 是落盘状态的第四种写操作：后续任何新增的「图库变空」路径（如换到空文件夹）都应产出它，而不是留空返回。
- 洗牌袋不跨启动保存的约束（ADR-0002）不变：重扫合并只动内存中的袋，落盘仍只有当前图、本轮进度与历史三项。
