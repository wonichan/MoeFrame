# Agent Note: 相框窗口层级采用会话内视口命令

Status: implemented

## Problem

用户需要从相框右键菜单控制无边框窗口的前后层级。窗口层级属于宿主平台行为；混入播放核心或配置持久化会把临时桌面操作变成播放状态或跨启动偏好。Windows 对置顶与置底提供的 Z 序语义不对称，产品行为需要明确。

## Decision

宿主在现有相框右键菜单提供“置于顶层”和“置于底层”两个可选项，并以勾号显示本次运行中最后请求的层级。宿主在 `FrameApp` 中保留当前进程的请求状态；启动状态为普通层级。选择一项后，宿主向根视口发送对应的 `WindowLevel` 命令。再次选择当前项发送普通层级，选择另一项直接切换。

置顶使用 Windows topmost 层级，直到用户切换或恢复普通层级。置底按 Windows 后端的 `HWND_BOTTOM` 语义把窗口移到操作发生时的 Z 序底端；之后创建或升起的窗口仍可能覆盖相框。控制不进入播放核心、不写入配置，也不增加菜单以外的入口。

该功能沿用 [宿主入口职责拆分](../../implemented/architecture/2026-11-22-host-module-split.md) 的 `FrameApp` 边界，不新增库层抽象。它复用 [无边框窗口验证工具](../../implemented/testing/2026-11-17-window-validation-harness.md) 确认的验证边界：视口命令测试不能替代 Windows 原生窗口验收，并复用 [相框按当前图像比例自适应宽度](../../implemented/feature/2026-11-22-image-driven-frame.md) 所在的相框右键菜单响应。它与 [托盘-only 化](../../implemented/feature/2026-11-22-tray-only.md) 无冲突，入口仍限相框右键菜单。

本功能不提前实施 [宿主层六个深挖候选](../../proposed/architecture/2026-11-21-host-deepening-plan.md)，不移动播放或几何决策。

## Alternatives considered

- 跨启动保存用户选择可让每次打开时沿用个人偏好；用户选择仅本次运行有效且启动保持普通层级，因此不增加配置字段或迁移。
- 增加独立的“普通层级”菜单项能让恢复操作更显眼；再次点击当前已选项已满足恢复需求，因此保留两个动作项。
- 持续强制置底能避免之后的普通窗口盖住相框，但需重复原生重排或监听系统窗口事件；产品接受 `HWND_BOTTOM` 的当前 Z 序语义，因此不实现持续强制。
- 宿主直接调用 Win32 `SetWindowPos` 可直接表达 Windows 原生操作；根视口命令提供对应接口并可在无窗口测试中观察，因此沿用它而不另建平台调用和生命周期路径。

## Consequences

- 运行期间的菜单勾选表示本进程最后请求的层级，不是持续读取的原生 Z 序。
- 自动化测试可验证真实菜单发出的根视口命令、切换、重复选择恢复普通层级和可见选中状态；它不证明 Windows 实际 Z 序。
- 本地已运行仓库唯一检查入口及 note tree/format 校验。Windows 原生置顶/置底、重启恢复行为仍需 Windows 实机验收；未实际验收时保持未验证。
