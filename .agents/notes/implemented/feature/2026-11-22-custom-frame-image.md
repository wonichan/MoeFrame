# Agent Note: V2 自定义相框图——洞自动检测、九宫格绘制与失效回退

Status: implemented

## Problem

工单 01 的地基里，自定义相框图模式只有外观枚举与全 0 内距占位：
用户没有入口选图，程序也不认识相框图。工单 03 要把这条线打通——
用户给一张自己画的 PNG，程序自动找到中间的透明洞、把插画裱进
洞里，图不合规或文件没了时也不能白屏或崩溃。

## Decision

- 新增库模块 `frame_art` 承担全部纯逻辑。分析函数吃解码后的
  RGBA 像素与「源图是否带透明通道」，按 spec 唯一规则找洞：
  从中心像素向外逐像素扩展，新条带整条全透明才并入，四边都
  推不动时到达包含中心的最大透明矩形；中心不透明、无透明
  通道、像素数据不完整都返回给用户看的中文拒绝原因。结论是
  洞矩形与四边内距（原始像素），并提供按「窗口内宽 ÷ 相框图
  原宽」的缩放系数换算窗口逻辑内距的方法。
- 加载在同一模块一次做完：文件头必须是 PNG（与产品图片加载
  同一套尺寸/分配上限），解码后先判透明通道再分析。相框图
  只存路径——`[display].frame_art` 配置键经 config_sync 镜像
  写回、启动包 HostInit 携带，文件从不复制进程序目录。
- 九宫格布局是本模块的纯函数：以洞为界切九区，宿主只画八区
  （洞区不画、插画在下层）；四角目标尺寸只由缩放系数决定，
  四边只沿长度方向拉伸，厚度系数只由宽度决定（外框变高时
  角与边厚不变）。宿主据此用 UV 子矩形逐区绘制，且不覆画
  相框图的任何透明像素；自定义生效时面板不铺不透明底，
  透明处直接透出桌面。
- 宿主持 `FrameArtHost` 状态（未选 / 已分析 / 回退带原因）：
  启动、每次切到自定义、选新图三处统一重新分析。生效内距收
  拢为宿主一个方法：自定义且分析成功时用缩放后的检测内距；
  回退或未选时按内置画框的当前内距——回退因此与内置模式共用
  内距与绘制，工单 02 的内置绘制落地后自动接上（本票落地时
  内置仍是工单 01 的零内距占位，回退视觉与内置一致）。回退
  不改已保存的外观模式与路径，设置窗在路径旁显示原因，日志
  记一行（与图片跳过日志同文件同格式）。
- 设置窗接线走既有会话机：外观组内自定义模式下多一个定界
  区块（选图按钮 + 路径 + 分析状态行）；选图经新增
  `Picks::frame_art_pick` / `SessionAction::PickFrameArt`，
  与选文件夹同规否决待结算草稿；宿主执行时弹 PNG 过滤的
  文件选择框，选定即存路径并重新分析，取消什么都不变。
- 插画绘制口径顺势对齐：画面只画在「外框 − 生效内距」的画面
  区域内（内距全 0 时即整窗，与 V1 一致），与解码口径（画面
  区域物理尺寸）同源；空状态提示也随之居中于画面区域。

## Testing

- 分析接缝（tests/frame_art.rs，像素夹具）：居中洞、偏置洞
  （仍含中心）、拍立得式宽下边、中心不透明拒绝、无透明通道
  拒绝、透明区内不透明点阻挡扩展；内距缩放按窗口宽度成比例。
- 布局接缝（同文件）：四角源/目标矩形、四边只沿长度拉伸
  （外框变高时角与边厚不变、变宽时系数随宽走）、洞区目标
  矩形。加载接缝（真实文件）：合规 PNG 通过、文件缺失拒绝、
  非 PNG 拒绝、无洞 PNG 拒绝、无透明通道 PNG 拒绝。
- 配置与会话：`frame_art` 键默认缺失不写回、往返保存与清除、
  非字符串修复为未选；启动包携带路径、save 写回落盘；选相框图
  否决待结算、同帧失焦被丢弃（与选文件夹同规两例）。
- 本机验证：Linux 刮擦副本全套 261 例全过（基线 241 + 本票
  新增 20）；Windows 目标 `cargo check --all-targets` 与
  `clippy -D warnings` 干净，`cargo fmt --check` 通过。九宫格
  上屏的角部不变形、回退后设置窗原因显示、透明处透出桌面
  只能在用户 Windows 机上核，工单 03 因此停在 needs-info。

## Alternatives considered

- 把自定义内距塞进 `AppearanceMode::insets()`：该方法无参，
  而自定义内距依赖分析结果与当前窗口宽度（缩放系数），塞
  进去要把分析状态挂到配置枚举上，层次倒置。宿主生效内距
  方法按消费方（几何、解码、绘制都在宿主）收拢，配置枚举
  只保留模式自身的静态内距。
- 分析放后台 worker 线程（与图片加载同路）：相框图分析是
  启动与切换时的低频一次性动作，同步解码一张受产品上限
  约束的 PNG 在毫秒量级；走 worker 要新增命令/回复对与
  序号裁决，收益不抵复杂度。
- 回退时把外观模式改写回内置落盘：spec 定案回退不改已保存
  的模式与路径——用户修好图后切回自定义即恢复，改写落盘会
  把一次临时故障变成永久设置丢失。

## Consequences

- 收益：自定义相框图全链路可用（选图 → 分析 → 缩放内距 →
  九宫格上屏 → 失效回退）；分析与布局都是库层纯函数，工单
  04 的异形只需接绘制与空状态，不再动口径。
- 代价与遗留：九宫格布局纯函数与工单 02 内置画框的布局纯
  函数是两处实现，spec 的「一个布局函数统一产出」留待专题
  收尾（最终评审）时合并，合并点已记在工单 03 的 Comments。
  本票按矩形外轮廓验收；外轮廓透明的完整异形行为（空状态
  洞透出、命中口径）在工单 04。自定义模式下相框图纹理按
  原图全分辨率上传，常驻内存增量随用户图大小而定，真机轮
  需留意稳态工作集预算。
