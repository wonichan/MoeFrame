# Agent Note: 开机自启以注册表实际状态为唯一真相，配置只是镜像，写失败靠「状态不动」回滚

Status: implemented

## Problem

[工单 21](../../../../.scratch/v1-exe/issues/21-autostart.md) 给相框菜单与设置窗加开机自启开关，要求界面、已保存配置与系统实际状态三者一致；写入失败时回到操作前状态、不弹窗、不伪报（父规格用户故事 57/58、第 10 节写死 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `MoeFrame` 项，且除该项外业务配置不进注册表）。核心风险是「配置布尔值撒谎」：用户在任务管理器或注册表里改过自启后，程序若只读自己的 config 镜像，开关显示的就是过时状态。

## Decision

- 真相分层：注册表 Run 项是唯一真相，config 的 `general.autostart` 降格为镜像。决策收进库 `autostart` 模块：`AutostartSync::startup(store, mirror)` 能读到实际状态时以它为准、与镜像不一致时返回回写值；读失败退回镜像、不回写。`toggle(store, target, command)` 先写系统，成功才更新自身状态并返回要保存的镜像值，失败返回 None 且状态不动——回滚不需要撤销动作，「从未动过」就是回滚。菜单与设置窗的复选框都从同一份 sync 状态渲染，失败时下一帧自然回到原值，全程不弹窗。
- 系统操作经 `AutostartStore` trait 接缝注入（工单标准 7 要求可控结果验证行为）：真实实现 `RegAutostartStore` 在宿主（winreg，Windows 门控依赖），读 = Run 项存在 `MoeFrame` 值即启用（NotFound 判未启用、其他错误上抛）；写启用 = 打开（或创建）Run 项后 set_value；写禁用 = delete_value，值不存在视为已禁用成功。判定只看值的有无、不比对已存命令是否指向当前 exe——外部改过目标时开关仍显示启用，用户关再开即按当前路径重写。
- 启动命令每次切换时按 `current_exe()` 现取现生成，路径整体加引号（库纯函数 autostart_command），含空格、中文、特殊字符都正确指向实际程序；程序被移动后下一次切换自动修正目标，不存旧路径。current_exe 取不到时直接放弃本次切换（状态不动）。
- 两处入口都只是收集意图、统一走宿主 apply_autostart（菜单走 menu_autostart 收集，与 menu_intent/menu_fit 同模式；设置窗走 picked_autostart）。自启路径不派发任何核心意图，不碰可见性、当前图、暂停与计时（工单标准 6）。

## Alternatives considered

- **开关直接读写 config 布尔、后台再同步注册表** — 正是规格要防的过时状态：外部改动后界面撒谎，且同步失败时没有确定的回滚点，拒绝。
- **每次渲染开关前都读注册表对齐** — 菜单/设置窗每帧读注册表是无谓的系统调用，运行中外部改动也不在本票范围（标准 3 约束的是启动读取与用户切换两个时点），拒绝；真相在启动对齐 + 本程序切换两处守住。
- **写启用前先比对已存命令、不同则视为未启用** — 把「指向旧路径的自启」判成未启用会让开关与系统（下次登录确实会启动旧路径）不一致，是另一种撒谎，拒绝。

## Testing

- 全量测试 176 项全绿（本票新增 6 项）：tests/autostart.rs 五项用可控替身验决策——启动实际优先且回写标记、读失败退回镜像、切换成功同步状态并给出保存值与命令、切换失败状态停在操作前且不报保存、命令对含空格/中文路径加引号；tests/config.rs 一项验镜像经真实文件往返。工单标准 7 明示：替身只证明应用行为，不代替真实系统验证。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。winreg 0.55 按需求文档 8.3 类别加入 Windows 门控依赖。
- 双轴审查（基线 `39c5896`）：Standards 一处硬违规已修——新类型插入时把 build_tray 的文档注释劈成两半（与工单 18/20 同型错误，已归位）；判断项采纳：toggle 改名 apply（set 语义）、开键样板抽 run_key。Spec 无缺失无蔓延，部分项处置：Run 键本身不存在原被当读失败退镜像——已改，键/值不存在都是确定的未启用，值在但类型不对经原始值判定为存在；其余如实勾注——配置保存失败被吞（系统已变、镜像靠启动对齐自愈，本会话内三方一致性短暂破缺）、运行中外部改动不重读（标准字面只约束启动与切换两个时点）、双入口展示与保存链在宿主内无自动化覆盖。
- 未验证：真实注册表上的启用/禁用/登录自启、任务管理器「启动」页的显示、失败路径（如权限被组策略锁定）在真机上的回滚表现——工单验收标准 8 明确要求实机记录且测试后恢复原状态，已并入合并实机清单（工单 10–21），本票因此转 `needs-info`，不标 resolved。

## Consequences

- config 的 autostart 自此是镜像而非独立设置：手改 config 的 autostart 不会改变系统自启，下次启动会被实际状态对齐回写——这是有意语义，README（工单 23）须写明开关以系统状态为准。
- 若日后要支持「运行中感知外部改动」，对齐点应加在菜单/设置窗打开那一刻（低频）而不是每帧；本模块的 startup 决策可直接复用，不要在宿主另写一套比对。
