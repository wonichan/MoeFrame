# Agent Note: V2 外观地基——透明创建、外观模式与四边内距几何

Status: implemented

## Problem

V2 相框外观专题（spec 见 `.scratch/v2-frame/spec.md`，决策过程见
[相框外观提案](../../proposed/feature/2026-11-22-picture-frame-appearance.md)）
需要一块地基：窗口创建方式、几何口径与解码口径都按「整窗即画面」
写死在 V1 里——窗口不透明创建、几何机只按整窗内尺寸推导、解码
目标取整个视口。画框一进来，这三处都要改：异形相框要求窗口透明
创建；外框尺寸 = 画面 + 四边内距，高度口径变为外框总高；解码
只需画面区域的像素。地基不先行，内置画框（工单 02）与自定义
相框图（工单 03）就没有可落的口径。

## Decision

工单 01 只做地基，不做任何画框绘制：

- 相框窗口永远以透明方式创建（根视口 `with_transparent(true)`）；
  极简与内置模式靠中央面板铺满视口的不透明填充（有图时纹理同样
  铺满）保持 V1 视觉，模式切换不需要重启进程。
- 外观模式（极简 / 内置画框 / 自定义相框图，默认内置画框）落
  `[display].appearance` 配置键，经 config_sync 的宿主状态镜像
  写回；宿主持有当前值，启动包 HostInit 携带初值。设置窗新增
  「外观」组（三项单选），点选经设置窗会话机产出
  `ApplyAppearance` 动作（与播放模式同规：同值守卫、顺序在模式
  之后、间隔预设之前），宿主执行时改值并写回。
- 几何泛化：`window_geom::Insets`（左/上/右/下各自独立）进入
  几何状态机的观察输入；推导改为画面高 = 外框高 − 上下内距、
  画面宽按图比例、外框宽 = 画面宽 + 左右内距，画面保持最小边
  约束；内距变化本身触发一次重新推导（外框总高不变时宽随之
  变）。落盘记录与恢复默认都按外框尺寸口径；内距全 0 时推导与
  V1 逐项一致，不需要配置迁移。
- 解码口径改为画面区域物理尺寸：宿主 `physical_target` 从窗口
  物理尺寸中减去内距的物理量；显示数据管线的接口不变。
- 本工单三种模式的内距都由 `AppearanceMode::insets()` 给出全 0
  占位：内置的真实内距（框宽 + 卡纸宽）由工单 02 供给，自定义
  的内距（相框图分析结果按比例缩放）由工单 03 供给，届时替换
  这个占位来源，几何与宿主接线不动。

## Testing

- 几何接缝（tests/window_geom.rs）：新增四例——四边不等内距的
  外框推导、内距全 0 与 V1 推导逐项一致、内距变化在同外框高下
  重新推导宽度、恢复默认按外框总高（含内距）落盘；既有 19 例
  不改断言全过。
- 配置与同步（tests/config.rs、tests/config_sync.rs）：外观默认
  内置且写回、三值解析、非法值修复回内置、`set_appearance_mode`
  往返、启动包携带外观初值、镜像写回落盘。
- 会话机（tests/settings_session.rs）：外观点选产生动作、同值
  守卫、与模式/间隔预设的动作顺序。
- 本机验证：Linux 刮擦副本全套 241 例全过；Windows 目标
  `cargo check --all-targets` 与 `clippy -D warnings` 干净；
  `cargo fmt --check` 通过。透明创建的真实视觉、设置窗切换的
  真机效果与资源复测（稳态工作集 ≤80MB、冷启动 ~0.3s 基线）
  只能在用户 Windows 机上核，工单 01 因此停在 needs-info，
  资源复测一条验收未勾。

## Alternatives considered

- 外观模式进行为核心（app_core）当作核心状态镜像：核心不关心
  绘制与内距，几何与解码口径都在宿主侧消费；放核心会让核心多
  一份与行为无关的状态。外观按开机自启的先例走宿主状态镜像，
  职责与消费方都在宿主一侧。
- 内距用几何机的 setter 注入（如 set_image_aspect 那样）：spec
  定案是观察输入增加四边内距——内距是每帧都可能变的观察量
  （滑杆拖动时逐帧变），进观察与既有「宿主只喂观察」形态一致，
  且恢复默认显式收内距参数，不留隐藏状态。
- 透明创建只在自定义模式启用（切换时重启窗口）：切换外观要
  无重启是定案口径，且按模式分两套创建路径会让真机验证面翻
  倍；永远透明 + 绘制层自绘不透明背景只多一条「面板必须铺满」
  的不变量，代价是透明合成的资源影响要复测（已挂工单验收）。

## Consequences

- 收益：02 与 03 落地时只需替换内距来源并加绘制，几何、解码、
  配置、设置窗四条线都不再动；内距全 0 的退化路径让 V1 行为有
  逐项对照的回归网。
- 代价：窗口透明合成对稳态工作集与冷启动的影响未测（真机项）；
  若明显恶化，按工单验收要回议 spec。设置窗高度因新增「外观」
  组从 700 提到 750。
- 占位边界：`AppearanceMode::insets()` 全 0 是明示的临时契约，
  02/03 必须替换它；在那之前内置/自定义模式视觉与极简无差别，
  这是工单 01 的预期状态，不是缺陷。
