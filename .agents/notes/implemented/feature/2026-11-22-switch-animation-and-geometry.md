# Agent Note: 切图交叉淡化与窗口几何动画——名义中心不漂，越界钳到 6px

Status: implemented

## Problem

切图当前是「加载完直接换纹理、窗口直接跳尺寸」。用户看到的是：没有过渡；新图按固定高度等比缩放，宽度变化可能超出屏幕；相框位置只保左上角，宽高变化后中心点漂移，多次切换后偏离原位。

`app_core` 其实已有 `Transition`、`Effect::StartTransition`、`Intent::TransitionCompleted` 和转场期间的导航队列，但宿主收到 `StartTransition` 后立即回送 `TransitionCompleted`，动画是空转的。`window_geom` 也是加载完就把新比例套进当前几何，下一帧直接 `SetInnerSize`，没有时间维度。

约束：egui 只给 `monitor_size`，没有显示器原点和工作区；要做到右边贴住屏幕可用区 6px，必须取 Win32 工作区。

## Decision

- 转场用 240ms 三次 ease-out 交叉淡化；`animation = none` 时立即完成。配置里的旧值 `slide` 继续合法，但宿主按交叉淡化处理，默认值不改，不迁移配置。首图加载、重扫后的首图不动画：只有已经显示一张图后切到另一张才起转场。
- 设置窗提供「切换动画」两档：无 / 交叉淡化。选择交叉淡化写回 `fade`；旧 `slide` 在设置窗按交叉淡化显示，选中它不触发重写；选择无写回 `none`。240ms 时长仍不开放配置。
- 转场期间 `incoming` 纹理保留为上层，旧纹理继续作为下层；两层都保持自身比例 fit 到当前画面区域，不拉伸。窗口边框逐帧重绘，旧图在宽高比变化时短暂留白，但不变形。
- 几何动画与图片淡化同一条时间轴、同一条 `ease_out_cubic`。`GeometryMachine` 在 `begin_image_transition(target_aspect, now, duration)` 里记录起止几何和目标时刻，`observe` 每帧插值内尺寸与位置，结束后停在目标；`transition_deadline_secs()` 让宿主安排重绘，不靠核心 `Tick` 推帧。
- 窗口位置按「名义中心」锚定，不按上一次显示出来的中心。`nominal_center` 初始化自存档位置与存档尺寸的中心；用户按住指针拖动或缩放时更新；无图时的位置变化也视为用户移动；首次放置、启动离屏钳制、恢复默认都同步更新。宽图被 6px 钳到边缘后，切回窄图仍回到原点，不把钳制后的中心当成新家。
- 目标尺寸仍以用户的名义高度为基准等比推导；只有目标宽度超过当前屏工作区可容纳宽度时，才临时缩小显示高度。名义高度不因这次临时缩小而改变：动画分支与落盘基准都用名义尺寸/名义位置结算，临时缩小不写回配置。切回竖图或重启后回到原来的高度。
- 工作区钳制在动画开始时取一次：用窗口句柄 `MonitorFromWindow` + `GetMonitorInfoW` 取 `rcWork`，物理像素除以当前 `pixels_per_point` 换成逻辑坐标；目标位置把越界边压到工作区边距 6px。取不到工作区时退回旧口径，不因此跳过动画。
- Windows 原生拖动/缩放的模态循环里 egui 可能收不到指针状态。宿主在 `StartDrag` / `BeginResize` 后置 `native_gesture_active`，下一帧并入 `pointer_down`，让几何机用循环结束后的最终位置/尺寸更新名义值；物理左键松开后清旗标。否则松手第一帧会按旧名义中心把窗口拉回，表现为「无法拖动」。
- 窗口位置和尺寸一起动画，不先瞬移再改尺寸；每帧对当前尺寸再做一次工作区钳制，保证中途不露到屏外。
- 动画期间用户按下指针拖动或缩放：立即发 `GeomCommand::TransitionInterrupted`，提交这次切换（不让核心一直等），停掉几何动画；松手后再按新中心做一次比例校正，不回弹。
- 转场期间显示数据刷新让路：`display_data` 的 `slide_active` 接 `crossfade.is_some()`，在飞的重载结果按 `RefreshDecision::Discard` 丢弃；转场结束后再按 250ms 停稳重发，避免窗口尺寸动画途中反复解码。
- `app_core` 的转场状态机、导航队列和提交点不动，本次只把宿主侧的「立即完成」换成真实计时；`TransitionCompleted` 仍在动画完成时回送，成功显示记账、预加载和落盘时机保持既有语义。

## Alternatives considered

- **只做图片淡化，窗口尺寸仍瞬间跳** — 改一处纹理绘制即可；但用户明确说尺寸跳变本身违和，且相框边缘会先跳再淡，拒绝。
- **只做窗口动画，图片直接换** — 窗口平滑了，但内容仍是硬切，与新图加载完成的瞬间对不上，拒绝。
- **把动画进度放进 `app_core`，由核心 Tick 推进** — 核心要多收渲染帧，且宿主渲染时钟与核心逻辑时钟双轨；沿用既有 `StartTransition` / `TransitionCompleted` 回送契约更薄，拒绝。
- **按当前显示中心锚定** — 实现简单，但宽图被钳到边缘后显示中心已变，下一次切换会继续以钳后中心为准，多次切换仍漂移；名义中心才是用户心里的「原位」，拒绝。
- **把临时缩小后的高度写回配置** — 配置会记住被屏幕逼出来的尺寸，切回竖图也回不到用户原来的高度；区分名义值与显示值，拒绝写回。
- **越界时只移动位置、不缩高** — 宽度超过整块工作区时位置怎么移都会露边；必须临时缩高，拒绝。
- **拖动中继续播放几何动画** — 会和用户抢方向盘，松手后还回弹；中断并立即提交，拒绝。
- **工作区用 egui `monitor_size` 近似** — 没有原点和工作区，任务栏/副屏场景下 6px 边距不可信；补 Win32 `GetMonitorInfoW`，拒绝近似。
- **动画时长做成配置项** — 设置窗只提供「无 / 交叉淡化」两档；把 240ms 也开放只会增加一个没人需要调的键，拒绝。

- `tests/window_geom.rs` 覆盖：尺寸与位置插值、终点无中间尺寸落盘、6px 工作区钳制、中心不漂、临时缩高不落盘、用户拖动中断动画、原生拖动丢指针事件后不回到旧位置、松手后按新中心校正。共 32 项通过。
- `tests/settings_session.rs` 覆盖切换动画点选的同值守卫与动作顺序；共 27 项通过。
- `src/bin/moe-frame/ui_regressions.rs` 覆盖转场透明度曲线与端点；`display_data` 既有 `slide_active` 测试覆盖转场中丢弃刷新。
- `tests/window_validation.rs` 13 项、`tests/settings_session.rs` 26 项保持通过。
- 验证入口：`./scripts/check.sh`（fmt + clippy `-D warnings` + `test --all-targets`），最后一次运行全部通过。
- 未做实机手感清单：窗口尺寸动画在 Windows 上依赖 `ViewportCommand::InnerSize` 的异步回传，240ms 内逐帧下发是否跟手、是否被 DWM 合并，需要在实机上看；6px 边距在副屏与不同 DPI 下的换算也需要实机确认。

- 原生拖动依赖 `native_gesture_active` 与物理左键状态兜底；若系统在模态循环结束后仍不派发释放事件，旗标最迟在下一帧按 `GetAsyncKeyState` 清除。
## Consequences

- 切图多等 240ms 才提交显示；连续导航仍只保留最后一个意图，动画期间不落盘。
- 交叉淡化同时持有新旧两张纹理，峰值内存增加一张当前图；转场结束后旧纹理随替换释放，不新增缓存。
- 旧图保持自身比例 fit，宽高比差异大时会短暂留白；这是不变形的代价。
- 几何动画依赖 `ViewportCommand::InnerSize` 异步回传；若系统合并或延迟，动画末段可能追帧，最终位置仍由下一次 `observe` 校正。
- 名义中心只在指针拖动/缩放、首次放置、启动钳制、恢复默认、无图时更新；键盘或系统触发的窗口移动目前不会改名义中心，下一次切图会回到旧中心。
- 工作区只按动画开始时的窗口所在显示器取一次；动画跨屏或中途 DPI 变化不在本次覆盖，仍需实机清单。
