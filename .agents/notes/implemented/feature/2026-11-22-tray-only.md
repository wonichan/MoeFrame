# Agent Note: 托盘-only 化：任务栏无图标，托盘三分支召回

Status: implemented

## Problem

程序运行时相框与设置窗各占一个任务栏图标，与「常驻桌面小工具」的定位不符（用户 2026-11-22 提出）。去掉任务栏按钮后，托盘成为唯一召回入口，而原托盘左键是纯切换：相框显示但被其他窗口盖住时点托盘，第一下反而把它藏起来，与「点托盘把它找回来」的直觉相反。

## Decision

- 相框主窗与设置窗的视口构建器都定死 `with_taskbar(false)`（创建时生效的构建期选项），无运行时开关、不加设置项。机制为 egui-winit 映射到 winit `skip_taskbar`，Windows 上走 `ITaskbarList::DeleteTab`：只删任务栏标签，不动窗口样式。
- Alt+Tab 明确不处理（用户定案）：相框显示时仍在 Alt+Tab 名单内；不引入 WS_EX_TOOLWINDOW 工具窗口样式。
- 托盘召回改三分支，判定在核心：`Intent::ToggleVisibilityRequested { focused }`——隐藏 → `ShowFrame`（显示并聚焦）；显示且有焦点 → `HideFrame`；显示但无焦点 → 新增 `Effect::RaiseFrame`（宿主只发 Focus 命令，可见性状态不变）。
- 焦点由宿主在点击帧采样 egui 视口焦点（`input.viewport().focused`），未知（None）按无焦点处理：只召回、不误藏。托盘左键、托盘菜单「显示/关闭相框」、几何状态机的 ShowFrame 路径共用同一意图与采样口径；几何路径只在隐藏时发出，永远走显示分支。

## Alternatives considered

- WS_EX_TOOLWINDOW 工具窗口样式（任务栏与 Alt+Tab 全清）：用户否决——需宿主手写 Win32 样式维护、防窗口重建丢样式，为 Alt+Tab 一项不值当。
- 设置项开关「在任务栏显示」：用户否决——托盘-only 是产品定位而非偏好，多一个开关多一组「窗口找不到」的状态组合。
- 托盘左键保持纯切换：被新场景否决——相框被盖住时第一下隐藏与召回直觉冲突。

## Testing

- 核心测试改写为三分支契约（toggling_visibility_follows_the_three_branch_recall_contract）：逐步断言三分支的效果与可见性状态；隐藏中轮播测试的召回调用同步新构造。
- 全量 230 项测试通过；Windows 目标 check 干净。
- 双轴 code-review（基线 2987e32）：Spec 轴功能标准全达标；Standards 轴一处硬问题（托盘事件分发处注释仍述旧纯切换语义）已修，「召回/唤回」用词统一为召回；内部字段名 show_hide 沿用旧配对属内部命名，记录为有意保留、不改名。
- 实机复测项已写入仓库根 real-machine-check-10-21.md：工单 17 一节左键项改三分支口径，新增「托盘-only 复测」一节（两窗任务栏无图标、设置窗召回、Alt+Tab 在列属预期），待实机回执后本专题工单转 resolved。

## Consequences

- 父规格 .scratch/v1-exe/spec.md 用户故事 53（左键切换相框显示与隐藏）被本决定取代（正文不改写，取代关系记于本笔记与工单 17 的对齐评论）。
- 任务栏不再是 MoeFrame 的任何入口；窗口的找寻路径唯一化为系统托盘（左键三分支召回、右键菜单）。
- 后续若再议 Alt+Tab，需另行决策 WS_EX_TOOLWINDOW 路线，不在本笔记范围。
- 托盘菜单项后来从三分支里拆出（菜单弹出时相框必失焦，「关闭相框」点不动）：
  [托盘菜单「关闭相框」点不动](../bug-fix/2026-11-22-tray-menu-visibility.md)。三分支自此只约束左键。
