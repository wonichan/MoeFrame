# Agent Note: 首张图纵向切片把行为规则放在无 IO 的核心里

Status: implemented

## Problem

[工单 10](../../../../.scratch/v1-exe/issues/10-first-image.md) 是第一个正式产品切片：真实相框要完成选文件夹、递归扫描、后台加载与显示，并落实父规格的配置契约。若行为规则直接写进 egui 回调，首次引导、取消、坏图跳过这些分支只能靠实机点按验证，后续轮播票也会无处复用；若复用工单 09 验证器的加载入口，产品会被迫继承它的编码大小预检，而父规格只授权以 Limits 约束解码输出。

## Decision

- 新增无 IO 的行为核心 `app_core::FrameCore`：宿主送入意图（Started、FolderPicked、ScanCompleted、LoadCompleted 等），核心返回效果（PickFolder、SaveFolder、Scan、LoadFirst、Exit）。首次只引导一次、取消不重弹、全坏图回空状态等规则全部在此判定，宿主只执行效果。这是本票的自动化行为测试接缝。
- 产品加载独立成 `loading` 模块，与验证器 `load_display` 结构平行但不共用入口：使用用户已确认的产品 Limits（12000 px / 96 MiB，见 [Limits 与峰值预算决定](../process/2026-11-20-product-limits-peak-budget.md)），拒绝发生在解码输出侧，不做编码大小预检；跳过记录含路径，超限另记原因，由工作线程追加写入 `moe_frame.log`。验证器接缝保持冻结，不动工单 09 的测量证据。
- 配置用 `toml_edit` 持有文档做字段级修复：坏字段只修该字段、合法手改与未知键在无关保存时原样保留；P1 三键（`pause_on_hover`、`animation`、`show_filename`）只保存与修复、不驱动行为；`current_image` 只保留字段，本票不做跨启动恢复。
- 宿主为单工作线程 + 序号防陈旧：每次新扫描都递增加载序号，换文件夹后到达的旧一轮加载结果按序号丢弃，不让上一个文件夹的图片回闪。
- 绘制按适应语义把纹理等比放进窗口矩形：窗口任意缩放时整图始终完整不变形，解码分辨率只影响清晰度。曾实现的「缩放稳定后按新物理目标重解码」在双轴审查中被判为工单 20 的范围且阈值无依据，已删除；跨启动位置与尺寸的写回同样留给工单 20，本票只读配置中已存的位置与尺寸开窗，无存档时才右下角内缩 24 px 放置。

## Alternatives considered

- **行为规则直接写进 egui 宿主** — 文件更少；但每个分支都要实机验证，且 11/12 票的轮播规则没有可复用的判定层，因此拒绝。
- **产品直接调用验证器 `load_display`** — 零重复；但会把编码大小预检带进产品，与父规格的 Limits 语义冲突，且验证器是冻结的测量证据面，因此接受加载管线在两个入口间重复存在（审查已记录此重复，日后若抽共享内部实现，两个入口都必须保持各自语义）。
- **配置整体反序列化重写** — 代码更短；但会抹掉合法手改、未知键与注释，违反配置契约，因此用 `toml_edit` 文档级编辑。

## Testing

- 全量 67 项测试通过（本票新增 26 项：config 6、library 5、loading 8、app_core 7），在 Linux 副本上运行；Windows 目标 `cargo check --all-targets`、clippy 与 `cargo fmt --check` 通过（clippy 仅剩验证器旧代码的 3 条既有警告）。测试走行为接缝与真实临时目录：字段级修复与手改保留、递归扫描与完整路径自然序、六种格式与 GIF 首帧、坏图/伪装/超限跳过与日志、核心状态机全部分支。
- 双轴审查（基线 `7f12ea5`）已处理：Spec 轴的适应裁剪、旧图回闪、每启必右下角三项已修；Standards 轴的回复布尔标志随重解码删除而消失、`animation` 改为枚举、测试临时目录助手已抽共享。两项驳回并记录理由：完整路径自然序是父规格 §3 对图库列表顺序的定义（§2 的「第一张」以此为准），不是 11/12 票的播放逻辑；`fit`/`fill` 是需求文档 §6 写定的配置键值合同，改名属配置格式变更，沿工单 09 的既有发现留待专门处理，不在本票静默更改。`natural_cmp` 的直接单测保留：前导零与码点序等边界语义无法只靠扫描层断言表达。
- 未验证：真实窗口显示与操作检查（工单 10 最后一条验收）只能在 Windows 实机完成，本票因此转 `needs-info` 等待实机记录，不标 resolved。

## Consequences

- 后续票可直接复用：行为核心的意图/效果接缝（11/12 票的轮播规则加在这里）、产品加载与跳过日志、配置文档级编辑。图库顺序自此固定为完整路径自然序。
- 遗留：加载管线双份实现（见 Alternatives）、`fit`/`fill` 术语与词汇表 Avoid 的冲突、窗口几何写回与 DPI 重定目标（工单 20）、V1 项目级一小时/峰值门（工单 22/23 前）。
