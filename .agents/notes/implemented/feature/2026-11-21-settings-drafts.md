# Agent Note: 草稿的提交时机靠「延迟一帧结算 + 基线比对」，不靠焦点事件的即时性

Status: implemented

## Problem

[工单 19](../../../../.scratch/v1-exe/issues/19-settings-drafts.md) 给设置窗补路径框、自定义秒数框与重新扫描按钮，语义由[决定 03](../../../../.scratch/v1-exe/issues/03-settings-boundary.md) 定死：打字只是草稿；失焦或回车才提交（先去首尾空白，回车后焦点留框内）；点重新扫描只扫已生效路径、绝不提交，且不能被它引起的失焦绕过；关闭丢弃未提交文字，不借关闭的失焦写入；菜单/预设改同一项时草稿作废、其他项不动；秒数解析失败保留上次有效值（不回退 30，与读配置修复是两套规则），越界整数钳制并显示结果；无效路径保留提交文本、图库落空、不弹窗。难点全在事件时序：点任何按钮都先让输入框失焦，「失焦即提交」的直写法会让重扫例外和关闭丢弃双双失效；菜单覆盖与结算之间也存在竞态。

## Decision

- 草稿状态全在宿主：每字段一份草稿文字 + 一份播种基线（草稿生成时的生效值）。打开设置窗时两字段强制重播种；每帧开头比对生效值与基线，偏离即作废重播种（菜单选文件夹、预设改间隔都走这条）；结算入口再比对一次基线，预设抢先在同一手势里改了值，待结算的草稿按 Discarded 处理，永不反向覆盖。
- 失焦不立即提交：焦点跟踪（回车识别、失焦识别，两个字段共用 `track_draft_field`）只记 `blurred`，帧末转存为 `pending_commit`，到下一帧的 show_settings 末尾、在本帧点选（预设/模式/显示方式）全部应用之后才结算。延迟一帧正是重扫例外的实现方式：重扫点击（无论与失焦同帧还是隔帧）在结算前被检查，命中即清掉待结算并只派发 RescanRequested（核心按已生效文件夹扫）。关闭分支优先级最高，清待结算且不看当帧的失焦记录。
- 「点相框算失焦」单独补一路：相框是另一个系统窗口，egui 的控件焦点是视口内记忆，跨窗口点击不保证触发 lost_focus。宿主采样设置窗视口的系统焦点（ViewportInfo.focused），由有到无且某字段还持有焦点记忆时，按该字段失焦处理——与窗内失焦汇入同一条延迟结算通道。
- 回车立即结算并 request_focus 把焦点抢回框内（单行 TextEdit 回车默认交出焦点，不抢回就违反决定）。
- 结算决策抽到库 `settings_draft`（settle_path_draft/settle_seconds_draft + DraftSettle 枚举）：输入（草稿、基线、生效值），输出（结果、框里显示文字、新基线）；宿主 commit_draft 只执行 CommitFolder/CommitInterval 两个派发。秒数解析在 config 的 parse_interval_draft（与读配置修复分开实现，文档与测试都按 ADR-0003 的两套规则写）：空白/小数/非数字返回 None 保留有效值；整数越界钳制；超 i64 位数的纯数字串按符号钳制。
- 路径提交只在文字异于生效值时派发 FolderPicked（同值不动，避免无谓地清续播状态）；无效/空白路径照样提交——核心原样保留该文件夹、扫描落空进 Empty、续播状态按换文件夹规则清，框里保留提交文本，重开按 core.folder() 重播种即原样显示。重扫按钮派发工单 16 的 RescanRequested，不在设置窗另设文件夹选择器。

## Alternatives considered

- **失焦立即提交、重扫按钮点击时回滚** — 回滚要撤销已派发的扫描/计时，FolderPicked 还清了续播状态，根本不可回滚，拒绝；延迟结算是唯一不撒谎的时序。
- **草稿状态进核心当意图/效果** — 草稿是纯 UI 机制（焦点、失焦、窗口激活），核心行为层不该知道输入框；结算决策抽纯函数已让可测部分可测，拒绝污染核心。
- **秒数输入做即时校验拦截（不许输入非数字）** — 决定 03 明确是提交时校验（解析失败保留有效值并显示），即时拦截会改变可输入的中间状态（如先删后输），拒绝。

## Testing

- 全量测试 161 项全绿（本票新增 8 项）：tests/config.rs 一项验 parse_interval_draft 的边界矩阵（区间内、双向越界钳制、超 i64 位数按符号钳制、小数/空白/科学计数/内嵌空格一律 None）；tests/settings_draft.rs 七项验结算语义——路径异值提交并保留文本、同值不动、被菜单覆盖作废、无无效/空白路径照样原样提交；秒数异值提交并显示钳制结果、解析失败恢复显示生效值、预设覆盖作废。派发后的图库/计时行为由工单 11/13/16 的既有核心测试守（FolderPicked/IntervalSelected/RescanRequested 同一入口）。
- Windows 目标 `cargo check --all-targets`、clippy 通过（仅余工单 09 验证程序的 3 个既有警告）；`cargo fmt` 已应用。
- 双轴审查（基线 `83020e3`）：Standards 轴无硬违规（词汇、ADR-0003 两套规则不合并、测试缝都成立），判断项处置：焦点跟踪块抽共用 helper、重播种抽 reseed_draft（三处共用）、parse_interval_draft 移到间隔常量三件套之后。Spec 轴无蔓延，逐项核对重扫例外（同帧/隔帧两种排布）、关闭丢弃（含已有待结算）、按字段覆盖、无效路径保留、秒数边界矩阵、暂停与同值提交全部成立；它点名的两处部分项都已补强：其一，标准 11 的自动化覆盖原只有解析规则——结算决策已抽库并补七项测试，剩下纯 UI 事件部分（回车焦点是否真留在框内、失焦触发时机）归实机标准 12；其二，「点相框算失焦」原先只靠视口内焦点机制、跨窗口不成立——已补视口系统焦点采样一路，实机清单点名验这一项。
- 未验证：回车后焦点是否留在框内、点相框是否即时提交、重扫不提交草稿的手感、关闭不误提交——工单验收标准 12 明确要求实机记录，已并入合并实机清单（工单 10–19），本票因此转 `needs-info`，不标 resolved。

## Consequences

- 工单 20 若给设置窗加新字段（如几何数值框），草稿类字段应沿用同一套：基线 + 延迟结算 + 结算函数进 settings_draft，不要再写第二套时序。
- 延迟结算意味着提交最多晚一帧发生；任何未来「提交后立刻读生效值」的宿主逻辑都要放在 show_settings 的结算之后，不要假设失焦当帧已生效。
- 视口系统焦点采样依赖 eframe 对即时视口的 focused 上报；若实机发现该信号不可靠，退路是只认窗内失焦并在工单里改记决定差异，不要悄悄换成轮询前台窗口的 Win32  hack。
