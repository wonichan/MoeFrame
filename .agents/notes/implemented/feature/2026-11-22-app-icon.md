# Agent Note: 应用图标接入（exe / 窗口 / 托盘）

Status: implemented

## Problem

程序没有自己的图标：exe 在资源管理器里是 Windows 默认 exe 图标，窗口
无图标，托盘用的是工单 17 时期的 48×48 占位图（红框白底小风景）。

## Decision

用户 2026-11-22 在四轮候选中选定 K6「少女侧颜」为母图（粉色蝴蝶结
相框 + 框内黑长直红丝带少女侧颜插画，生成源图 1600×1600）。一套
母图、三处落点：

- `assets/icon.png`（512×512）与多尺寸 `assets/icon.ico`
  （16/20/24/32/40/48/64/128/256）入库。
- exe 文件图标：既有 build.rs 末尾追加一段，仅在 Windows 宿主上用
  winresource（新增 `[target.'cfg(windows)'.build-dependencies]`）把
  icon.ico 编入资源；编译失败只 `cargo:warning` 不中断——图标是外观
  项，不该挡住构建。build.rs 的 rerun-if-changed 名单加了 icon.ico。
- 窗口图标：`tray.rs` 新增 `app_icon_data()`（与托盘图同居一处管
  图标解码），主视口与设置视口都 `.with_icon(...)`；托盘-only 之后
  它主要供 Alt+Tab 列表识别。
- 托盘图标：`assets/tray-icon.png` 换成母图的 48×48 渲染，文件名与
  加载代码不变；其文档注释里对旧占位图的描述已同步更新。

## Alternatives considered

- 只设窗口图标、不嵌 exe 资源：资源管理器里 exe 依旧是默认图标，
  而用户指出的正是文件图标，不达标。
- 用 `embed-resource` 等其他资源 crate：winresource 是该用途的
  事实标准且构建期零运行时成本，无理由另选。
- 托盘图单独设计小尺寸专用图：母图在 48px 下轮廓仍可辨（粉框 +
  深色头发块），一套图保持识别一致性，专用图留待真机看过再议。

## Testing

- Windows 目标 clippy（-D warnings）干净；全量测试 230/230 通过。
- ico 文件经 `file` 核验含 9 个尺寸条目。
- 未验证项：exe 资源图标只在 Windows 宿主原生构建时编入，本机
  （Linux 交叉检查）按设计跳过——真机确认留工单（下轮构建后看
  资源管理器中的 exe 图标）。

## Consequences

- 新增一个 Windows-only 构建依赖 winresource；运行时依赖不变。
- 换图标只需替换 assets 下三件资产（ico 需按尺寸套重新生成），
  代码不用动。
