# Agent Note: 无边框窗口验证不代替人工验收

Status: implemented

## Problem

[08 窗口最小验证](../../../../.scratch/v1-exe/issues/08-window-validation.md)必须先隔离窗口能力风险，再解除正式窗口实现的门禁。API 返回成功、截图及编译结果都不能证明用户实际拖动与缩放可用；把验证程序写成半个相框也会混入尚未通过的窗口假设。

## Decision

只提供 `window-validation` 独立 Rust 程序、[操作清单](../../../../docs/window-validation.md)和本地诊断日志，沿用 eframe/egui 0.37.0。内容仅显示诊断，不加载用户图片、不恢复配置、不做轮播、托盘或宽高比锁定。最大化与还原使用验证专用快捷键，不加入正式产品按钮。

窗口动作由左键按下事件立即发起；边角命中先于内容移动，最大化或状态未知时不发起边缘缩放。发出的视口命令只记录为请求，不记录为通过。原生 DPI、客户区尺寸与 egui 逻辑尺寸分开记录，失败或未知值不能变成零值或通过。

用户已确认的自动化接缝只有两处：验证程序的 egui 输入到视口命令入口，以及诊断日志的真实文件入口。测试不直接调用私有命中函数，也不以 mock 返回成功证明 Windows 能力。

## Contracts and provenance

- 多次 UI pass 不重复请求；最大化命令排队期间禁止边缘缩放，等实际原生状态确认后解除守卫。
- `NativeOptions::window_builder` 设置不激活和禁用文件拖入；egui-winit 会为无装饰窗口开启 Windows 阴影，因此在 `CreationContext` 获取原生窗口、首次显示前关闭阴影。0.37.0 中该扩展方法属于 `WindowExtWindows` 的窗口方法，不是旧路线笔记描述的 builder 方法；不修改旧路线票。
- `physical_client` 是 winit 物理客户区；`win32_client` 是原始 Win32 读数；`system_logical_client` 是显式标注的换算值。对 DPI 虚拟化的判断仍依赖实际环境比较。
- 构建脚本嵌入编译器、目标、Git revision/dirty 与锁定依赖版本。每次运行使用独立文件，日志只标记 `unverified`；原生/后端错误不伪装成成功。
- 本机实际为 Win11 x64 Build 26200、缩放 150%，与计划 26100 不同。用户已于 2026-11-17 实机操作并确认本机窗口能力通过；Build 26100、Win10、100% 缩放与混合 DPI 双屏仍保持未验证，不沿用本机结果。

## Alternatives considered

- **等待 `drag_started` 或持续 `dragged` 后调用窗口动作**：方便沿用控件阈值，但会错过原生拖动/缩放要求的按下时机，并容易重复请求。本次只验证原生能力，按下即请求；正式相框手势仍按 ADR 单独实现。
- **仅将 egui 逻辑尺寸乘缩放系数作为物理客户区**：不需额外原生读取，但不能独立核对 DPI 虚拟化。保留原生读数与 egui 读数，不把换算冒充实测。

## Consequences

- 收益：正式窗口实现之前可单独定位边角命中、按下时机、最大化守卫和 DPI 问题；日志保留实际构建和运行条件。
- 代价：多维护少量构建/诊断代码、每 250ms 的观测刷新；这些不扩展成产品持久化或遥测。
- 局限：原生请求可能无效果；本机验证不能覆盖正式产品集成与其他 Windows/DPI/多屏环境。用户确认前不完成 08、不启动被它阻塞的后继票；失败先核对调用，再另开备选票，不更换框架。
