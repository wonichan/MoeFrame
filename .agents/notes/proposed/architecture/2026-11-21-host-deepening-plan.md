# Agent Note: 宿主层六个深挖候选定案（架构评审 + grilling）

Status: proposed

## Problem

工单 10–21 之后，库层模块（app_core、playlist、gesture、config）深度良好，但宿主 `src/bin/moe-frame.rs`（评审时 1656 行，近 14 个提交改 8 次；2026-11-22 已按职责机械拆到 `src/bin/moe-frame/`，入口剩 220 行，见 [拆分笔记](../../implemented/architecture/2026-11-22-host-module-split.md)，六个候选的定案不受影响）没有任何 module 边界：工单 17/18 之间发生分叉，18 票起的新职责（显示方式、草稿、几何、自启）全部绕开行为核心、以「字段 + 方法」直接长在 FrameApp 上。后果是宿主侧行为（纹理转正记账、设置窗帧编排、几何生命周期、托盘接线、重绘调度等）零自动化覆盖，只靠未执行的实机清单兜底；「当前纹理与所显示图片的口径一致」这类不变量靠三处手抄维系；每个新持久化设置要改六处。2026-11-21 用 improve-codebase-architecture 技能完成架构评审（六个 deepening 候选），并逐个 grilling 走完决策树，结论如下。本笔记记录定案，实施另行拆票。

## Proposal

总顺序：候选 1 → 2 → 3 → 4 → 6 → 实机清单（验新代码）→ 工单 22/23 发布门 → 候选 5。共同形状：库层 egui-free 的事件进/决策出 module，宿主只采样、渲染、执行；module 之间不横向通信，一切经宿主转交；测试只留一个测试面（replace-don't-layer）。

1. **显示数据管线 → 库 module `display_data`**（GLOSSARY 已新增「显示数据」，提交 a878539）：管显示数据的记账、转正、过期判定与重载决策；纹理句柄留宿主，只认当前/传入两槽，重载是「替换当前槽」决策；废除 RELOAD_SEQ 哨兵，刷新走 worker 独立命令类别，全部加载流量（导航/预载/刷新）经它中转、core 不改；预载缓存键的口径归它、存储归 worker；物理目标 250 ms 防抖归它计时；刷新失败明文策略 = 保持旧纹理、不重试、不提示；滑动绘制数学留宿主不动。
2. **设置窗会话机 → 库 module `settings_session`**：管整个设置窗会话（开/关/重开种子、两草稿字段全部时序、即时控件的点选收集与应用顺序），定位留宿主；settings_draft 被吸收为内部实现，测试改走新 interface；延迟一帧结算内化为「帧结束」事件规则，关闭/重扫在同帧先取消待结算；外部改值不设通知通道，靠每帧生效值快照比对作废草稿；落盘类动作先宿主直执，候选 4 落地时改道。
3. **导航决策收拢到 Playlist**：候选计算、落位方式、落位记账、恢复/重扫/缺失替代候选整段下沉；RandomSource 所有权移入 Playlist；备袋内化为落位记账的自检；落位标记类型归 Playlist 定义、core 只携带不解释；续播数据改由 Playlist 产出只读快照，core 不再摸 seen/history/游标；core 只保留计时、在飞/排队、转场、视图，入参只减不打包；测试随决策搬家。
4. **持久化镜像与启动装配 → 库 module `config_sync`**：两头收——启动翻译产出一个启动包（core 构造入参 + 宿主初值），全部镜像写回经它落盘（core 的 Save 系列 Effect、宿主直写的显示方式/几何/锁定/自启镜像）；ConfigStore 降为其背后的文件 adapter 不合并；自启只收写回与启动对账装配，AutostartSync 决策不搬；写回失败统一口径 = 不阻塞、不弹窗、不重试、记一行日志、靠下次启动对账收敛；退出冲刷归它收尾，Exit 臂只发请求；候选 2 的落盘动作在此改道。
5. **双解码管线合流（排在 22/23 发布门之后，最后做）**：产品解码实现与产品类型（DisplayMode、DisplayImage、DecodeError、DecodeLimits）迁产品侧，loading.rs 就地演进承接、不改名；decode_validation 只剩验证装配 + 薄 adapter（可独立传 Limits 的实验入口），decode-validation 二进制保留；fit/fill 计算三份合一、取整政策只定义一次；工单 09 的 encoded-size 预检分歧一并裁决关闭（Limits 只按解码输出判定），旧笔记以新笔记取代并交叉链接。
6. **窗口几何生命周期 → 库层状态机（window_geom 就地演进）**：纯算术被吸收为内部实现；宿主每帧喂观察值、状态机返回抽象命令；只产出待保存几何，落盘归 config_sync，初值来自启动包；多显示器已知限制（副屏误钳）只搬家不修复、行为不变；宽高比锁定的比例捕获归状态机（用最近观察值），开关动作经 settings_session 发出、宿主转发。此候选的宽高比锁定部分后续由 [相框按当前图像比例自适应宽度](../../../../.agents/notes/implemented/feature/2026-11-22-image-driven-frame.md) 取代。本候选排第五，是六个里唯一可无损推迟到 V1 之后的一项。

## Acceptance criteria

- 六个候选各拆一张工单实施，每票满足：新 module 的 interface 上有行为测试且全量测试绿、双轴 code-review 通过、宿主文件行数较实施前下降。
- 候选 1：代码中不再存在 RELOAD_SEQ 或等价哨兵；纹理转正只经 display_data 的决策发生。
- 候选 2：重扫否决、关闭丢弃、帧结束结算、快照作废四条时序规则各有行为测试。
- 候选 3：core 中不再存在落位枚举与替代候选自由函数；导航决策只有一个测试面。
- 候选 4：宿主代码不再直接调用 ConfigStore 的 setter；新增一个持久化设置的改动只落 config_sync 与 UI 两处。
- 候选 5：交叉等价测试在合流前建立并在合流后保留；产品代码中解码实现只剩一份。
- 候选 6：几何生命周期状态迁移有行为测试；副屏误钳行为与实施前一致（只搬家）。
- 实机清单在候选 1/2/3/4/6 之后、22/23 发布门之前执行完毕。

## Risks

- 候选 1/2/3/4/6 连续重构宿主，若中途实机清单发现原有 bug，归因成本上升；缓解：每票全量测试 + 双轴审查，清单紧跟其后。
- 候选 4 与候选 2 的改道点若顺序颠倒，会出现两套写回路径并存期；缓解：按定案顺序实施，改道只发生一次。
- 候选 5 若被提前到发布门之前，工单 09 实测证据链失效；缓解：顺序已钉死，实施拆票时在票面重申。

## Alternatives considered

- 宿主内持有者（候选 1/2/6 的备选）：能直接拿 egui 句柄，但测不到，等于把热点换个房间——否决，本次深挖的目的就是给宿主行为建立可测 interface。
- 哨兵只换枚举标签、保留单一 Load 命令多路（候选 1 备选）：leaky abstraction 的根是借道核心序号空间，换标签不治本——否决。
- 合流先行 + 等价测试护栏（候选 5 备选）：技术上可行，但 22/23 发布门将测到新实现，工单 09 的实测证据链要重新解释——否决，发布门用原接缝闭合后再合流。
- 把 ConfigStore 并入 config_sync（候选 4 备选）：config.rs 的字段级修复结构健康且测试充分，合并只会把新 module 撑成两个——否决，降为 adapter。
- 草稿结算、几何纯函数保留独立公开面（候选 2/6 备选）：同一语义两个测试面，改一处规则要改两处测试——否决，统一吸收。

## Testing

- 每个候选实施时按既有流程：TDD 在新 module 的 interface 上先行，全量测试收尾，双轴 code-review 不变。
- 测试迁移遵循 replace-don't-layer：settings_draft、window_geom 的现有用例改打新 interface；app_core 中断言候选/落位的用例搬到 Playlist 测试面。
- 候选 5 合流前先建交叉等价测试：同一样本集、多种 Limits 下两条管线的输出尺寸与拒绝结果一致；其中 encoded 预检差异记录为「已知差异」，不列入等价项。
- 宿主接线仍无自动化覆盖的部分（托盘、关闭拦截、视口命令翻译）继续靠实机清单；清单排在候选 1/2/3/4/6 之后执行，验的是新代码。
- 本笔记为 proposed 状态：六个候选均未实施，实施时各自另写 implemented 笔记。

## Consequences

- 工单 22（发布门）的开工时点后移：先做候选 1/2/3/4/6 与实机清单，发布门再用工单 09 原接缝完成 1 小时轮播与峰值复测；候选 5 在发布之后，不挡 V1 交付。
- 后续新增持久化设置、设置窗控件、显示口径变更的改动面各自收敛到一个 module；宿主文件预期显著变薄。
- GLOSSARY 已新增「显示数据」；「会话」「镜像」「窗口几何」判定为结构词，不入术语表。
- 候选 6 若推迟，window_geom 维持现状即可，不影响其余候选与发布门。
- 候选 5 落地时须同步更新 docs/decode-validation.md 并新写取代工单 09 处置的笔记（见 Decision 第 5 条）。
