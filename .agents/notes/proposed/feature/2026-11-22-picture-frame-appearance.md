# Agent Note: V2 相框外观（画框）设计定案

Status: proposed

## Problem

现行相框是无边框裸窗口：图片贴边铺满整个窗口，没有描边、没有
留白。用户 2026-11-22 认为这样不够美观，希望加上像真实相框一样
把插画裱起来的画框，并要求支持用户自己出图提供相框、且要能做
异形相框。这与 V1 需求 FR-309（P0：内边距 ≤4px、仅 1px 描边、
明确「禁止宽边框 / 大留白的相框式设计」）正面冲突，也与术语表
把「相框」定义为「无边框的桌面窗口」冲突。需要一次显式的方向
修订，而不是悄悄改样式。

## Proposal

2026-11-22 三轮 grilling 达成共识，全文见
`.scratch/v2-frame/spec.md`，要点：

- 外观三选一（极简 / 内置画框 / 自定义相框图），默认内置画框，
  极简保留；设置只进设置窗「外观」组，右键菜单不动。
- 内置画框三层（框体 + 卡纸 + 内沿），四款预设（胡桃木默认），
  框宽/卡纸宽双滑杆，自绘软阴影。
- 尺寸口径改：高度 = 外框总高度；内距四边独立建模；解码口径
  改为画面区域尺寸。插画完整不裁切不动。
- 自定义相框图：PNG 九宫格 + 透明洞自动检测，框厚按窗口宽
  等比缩放，只存路径，失效回退内置默认框并给出原因。
- 异形：相框窗口永远透明创建（极简/内置自绘不透明背景），
  自定义图透明外轮廓直接透出桌面；本期不做点击穿透、无阴影、
  缩放带维持矩形 8px、洞恒为矩形、空状态框在洞透。
- 范围定为 **V2**：v0.1.0 先行发布，本专题不进。

配套文档动作：GLOSSARY 已改「相框」定义并新增外观/画框/框体/
卡纸/内距/相框图/异形相框七个词条；FR-309 的改写与新增 FR-31x
条款在 V2 生效时写入需求文档（措辞已备在 spec 的「需求变更」）。

## Alternatives considered

- 只做程序绘制的矢量画框、不支持自定义图：用户明确要求「用户
  可能自己出图提供相框」，不取。
- 自定义图整幅缩放覆盖（非九宫格）：窗口比例随插画变化时角部
  图案必然拉伸变形，且洞与插画比例对不齐，不取。
- 异形一并做点击穿透：需要按像素接管 Windows 命中测试，平台
  风险与本专题体量不匹配，推迟二期单独议。
- 用原生窗口阴影：阴影按矩形窗口投，套异形必穿帮；内置模式
  改自绘软阴影，异形本期无阴影。

## Risks

- 相框窗口改透明创建后，Windows 合成路径与不透明窗口不同，
  稳态工作集（现预算 ≤80MB）与冷启动需在 V2 工单 01 后复测，
  若明显恶化需回议本定案。
- 洞自动检测只认「从中心扩展的全透明矩形」一条规则：半透明
  像素、多块透明区域等作者手法会被判无效，靠设置窗的明确
  报错兜底；规则若被证明太严，V2 内再放宽并改 spec。
- FR-309 仍是 v0.1.0 的验收依据：本定案只落 spec 与笔记，
  需求文档在 V2 生效前不改动，避免污染工单 23 的验收口径。

## Acceptance criteria

- V2 启动时按 `.scratch/v2-frame/issues/01–04` 顺序实施，每票
  满足其验收标准、全量测试绿、双轴 code-review 通过。
- 极简模式在工单 01 之后与 V1 视觉逐项一致（真机清单复核）。
- FR-309 改写与 FR-31x 条款在 V2 实施时同步落入需求文档，
  不与本 spec 矛盾。
