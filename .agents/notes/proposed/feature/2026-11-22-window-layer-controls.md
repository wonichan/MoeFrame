# Agent Note: 相框窗口层级采用会话内视口命令

Status: proposed

## Problem

用户需要从相框右键菜单控制无边框窗口的前后层级。窗口层级属于宿主平台行为；若混入播放核心或配置持久化，会把临时桌面操作变成图库/播放状态或跨启动偏好。Windows 对置顶与置底提供的 Z 序语义也不对称，产品行为必须说清楚。

## Proposal

宿主在现有相框右键菜单提供置顶与置底两项，使用根视口的窗口层级命令表达普通、置顶和置底请求。宿主只保留当前进程的请求状态；启动为普通层级。重复选择当前项恢复普通层级，选择另一项直接切换，菜单显示本次运行的选择。

置顶使用 Windows topmost 层级，直到用户切换或恢复普通层级。置底按 Windows 后端的 `HWND_BOTTOM` 语义把窗口移到操作发生时的 Z 序底端，不保证后续仍在新窗口之后。控制不进入播放核心、不改配置、不增加其他入口。

自动化测试沿用已确认的宿主 UI 接缝：合成 egui 输入驱动真实菜单，检查根视口命令与用户可见的菜单选择状态。Windows 实机仍需验证原生 Z 序效果。

## Alternatives considered

- **跨启动保存用户选择** — 可让每次打开时沿用个人偏好；用户明确选择仅本次运行有效，且启动保持普通层级，因此不增加配置字段或迁移。
- **增加独立的“普通层级”菜单项** — 普通层级更显眼；用户接受再次点击当前已选项来恢复普通层级，因此保留两个动作项即可。
- **持续强制置底，避免之后的普通窗口盖住相框** — 能给出更强的“始终在后”承诺，但需要重复原生重排或监听系统窗口事件；用户接受 `HWND_BOTTOM` 的当前 Z 序语义，因此不实现持续强制。
- **宿主直接调用 Win32 `SetWindowPos`** — 可直接表达 Windows 原生操作；现有根视口命令已提供相应层级接口，沿用它能让 UI 行为在无原生窗口测试中可观察，并避免另建平台调用与生命周期路径。

## Acceptance criteria

- 真实相框菜单发出 `AlwaysOnTop`、`AlwaysOnBottom` 与 `Normal` 根视口命令，覆盖互切和再次选择。
- 新进程默认普通层级，当前请求状态不落盘；图片、播放和窗口几何行为不变。
- 自动测试在既有宿主 UI 回归面观察真实菜单输出，不复制生产逻辑；Windows 实机单独确认原生窗口顺序。

## Risks

- 置底后的实际顺序会被之后出现或升起的窗口改变；菜单指示的是本进程最后请求的层级，不是持续读取的原生 Z 序。
- 合成 UI 测试只能证明 egui 发出正确命令，不能证明 Windows 原生行为；实机验收缺失时必须保留未验证标记。
- 正式宿主测试在 Windows-only binary 中运行；非 Windows CI 不能替代 Windows 目标的编译和测试。
