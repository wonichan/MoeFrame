# 相框窗口层级

Status: ready-for-agent

## Problem Statement

用户希望能直接控制无边框相框窗口在桌面上的前后层级。当前相框启动时处于普通窗口层级，右键菜单没有置顶或置底操作；需要在不影响图片显示、播放和窗口几何行为的情况下提供这两个操作。

## Solution

在相框右键菜单中加入“置于顶层”和“置于底层”两项。置顶在本次运行期间保持生效，直到切换层级或再次选择置顶恢复普通层级。置底将窗口移到点击时的 Z 序底端，但不承诺后续仍低于所有窗口。菜单显示本次运行中请求的层级；应用重启后回到普通层级。

## User Stories
1. 作为 MoeFrame 用户，我希望从相框右键菜单选择“置于顶层”，以便相框在本次运行期间保持在普通窗口上方。
2. 作为 MoeFrame 用户，我希望从相框右键菜单选择“置于底层”，以便相框让到点击时已有的其他窗口之后。
3. 作为 MoeFrame 用户，我希望菜单显示本次运行中选择的层级，以便知道再次点击哪项会恢复普通层级。
4. 作为 MoeFrame 用户，我希望再次点击当前已选择的置顶或置底项时恢复普通层级，以便不需要额外的复位菜单项。
5. 作为 MoeFrame 用户，我希望能直接从置顶切换到置底或反向切换，以便新选择立即替代当前选择。
6. 作为 MoeFrame 用户，我希望置底操作只承诺移到当前 Z 序底端，以便知道之后出现或升起的窗口仍可能盖住相框。
7. 作为 MoeFrame 用户，我希望应用重启后相框回到普通层级，以便临时选择不改变之后启动时的桌面行为。
8. 作为 MoeFrame 用户，我希望未选择层级时保持现有普通层级启动行为，以便原有默认窗口行为不变。
9. 作为 MoeFrame 用户，我希望层级操作只改变相框窗口顺序，以便当前图片、播放状态、计时、位置和大小都保持不变。
10. 作为 MoeFrame 用户，我希望层级操作仍可从现有右键菜单访问，以便不需要新的悬停条、设置窗或托盘入口。
## Implementation Decisions

- 层级控制属于宿主窗口行为，不加入播放核心状态机，也不改图片、播放、托盘或几何状态。
- 使用运行时窗口层级命令控制根相框窗口。普通层级、始终置顶和置底请求分别映射到相应窗口层级。
- 置顶使用 Windows topmost 层级，在本次进程运行期间保持，直到改选其他层级。
- 置底按 Windows 后端的 `HWND_BOTTOM` 语义把窗口放到操作发生时的 Z 序底端；后续窗口可以覆盖它。不得将此行为描述为始终位于所有普通窗口之后。
- 右键菜单保留两个层级操作项并显示当前会话请求的层级。再次选择当前项时发出普通层级请求；选择另一项则直接切换。
- 层级选择只保存在本次运行的宿主内存状态中。每次启动仍使用普通层级，不新增配置字段或落盘行为。
- 不新增第三个普通层级菜单项，不新增悬停条、快捷键、设置窗控件或托盘命令。

## Testing Decisions

- 好的测试通过用户可观察行为验证菜单选择及其窗口层级命令，不断言内部字段布局或底层实现细节。
- 将现有宿主 UI 回归接缝扩展为驱动真实 `FrameApp::ui` 菜单的无窗口测试；使用合成 egui 指针输入，并检查根视口输出的层级命令。覆盖置顶、置底、置顶与置底互切、重复选择恢复普通层级，以及命令后的菜单选择状态。
- 如构造真实宿主需要测试装配，只新增最小测试用构造方式；不复制一份仅供测试的右键菜单实现。
- 先例是现有的相框右键菜单打开回归测试，以及窗口验证测试中对根视口命令输出的断言。
- 自动化测试不能证明 Windows 实际 Z 序。Windows 实机验收需确认置顶可压过普通窗口、置底会移到当时的窗口队列之后且可能被后来窗口盖住、再次选择当前项恢复普通层级，并确认重启后为普通层级。
- 所有仓库自动检查通过 `scripts/check.sh` 唯一入口运行。

## Out of Scope

- 将层级选择跨重启保存到配置。
- 保证置底窗口持续低于之后创建或激活的窗口，或通过轮询、系统钩子反复重排窗口。
- 修改默认启动层级、窗口位置/大小、图片显示、播放/暂停、轮播计时或相框可见性。
- 为图像内容或多个画布对象排序；当前相框一次显示一张图片，没有对象层级模型。
- 在设置窗、悬停条、托盘、快捷键或其他窗口中增加入口。
- 在 Windows 以外的平台提供相同的原生层级保证。

## Further Notes

当前项目固定的 winit Windows 后端将置顶映射为 `HWND_TOPMOST`、置底映射为 `HWND_BOTTOM`。因此两个菜单操作的持续性并不对称：置顶是 topmost 层级，置底是 Z 序底端请求。此差异已由用户确认接受。
