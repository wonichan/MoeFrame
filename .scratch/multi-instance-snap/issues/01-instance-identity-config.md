# 01: 实例身份与配置隔离（编号认领 / 实例段迁移 / 写入纪律 / 级联初始位置）

**What to build:** 给每个 MoeFrame 进程一个实例编号作为身份，并把配置从「全局一份、整文件覆写」改成「一份文件、实例段隔离」：`config.toml` 新增 `[[instances]]` 段存各实例的图库与几何，全局段继续存共享设置；写入改为写前重读、只改自己那段，修掉双开互相回滚。无落盘几何的新实例按级联偏移开窗。本票是专题地基，不含任何吸附行为。

**Blocked by:** 无（地基票）

**Status:** ready-for-agent

## Acceptance criteria

代码项：

- [ ] 编号认领：实例启动时认领最小空缺编号（app 目录下编号锁文件占位），进程退出释放；两个实例同时启动不认领同一编号，第二个实例退出后第三个实例能复用其编号。有对应自动化测试或可复现的并发验证记录。
- [ ] 实例段读写：`[[instances]]` 每段含编号、`image_folder`、`window` 几何；实例只读写自己那段的图库与几何，A 实例切图库/移位落盘不改 B 实例段的任何字节级内容（以解析后字段比对为准）。
- [ ] 迁移：老配置（无实例段）首次启动时，1 号实例继承现有 `image_folder` 与 `window`，位置与图库与升级前一致；迁移只发生一次，重复启动不重复生成实例段、不丢数据。
- [ ] 写入纪律：所有写回路径（几何落盘、设置落盘、退出冲刷）统一走「重读磁盘当前文档 → 只改自己实例段与全局段中自己改的键 → 写回」；构造「A 改图库、B 改几何、交错写回」的测试场景，最终文件两处改动都在，无一被回滚。
- [ ] 级联初始位置：认领编号无落盘几何时，新窗相对上一扇已开相框偏移 +24px 打开（横纵各 +24，仍受既有工作区钳制约束）；有落盘几何时严格按落盘位置开，不偏移。
- [ ] 单实例行为不回归：只开一扇时，配置读写、几何落盘、退出冲刷与现行行为一致；既有 config/config_sync/window_geom 测试全绿（因结构变更必须改的断言逐条在 Comments 注明理由）。
- [ ] `scripts/check.sh` 通过（唯一检查入口：fmt + clippy `-D warnings` + test `--all-targets`）；在本 VM 等跑不了该脚本的环境，沿用 Linux 测试副本 + Windows 目标 check/clippy/fmt 替代口径并如实记录，不冒充跑过本体。

实机项（汇总进工单 04 的实机清单，本票置 needs-info 时回填勾选）：

- [ ] 实机：双开 exe，两扇位置/图库各自独立调整后分别重启，各自恢复自己的位置与图库，无串扰。
- [ ] 实机：老配置升级首启，第一扇位置与图库与升级前一致。

## Context

专题 spec：[多实例吸附](../spec.md) 第 1、6 节。现状事实（2026-11-23 探查）：配置为单一全局结构 `Config{image_folder, window, playback, display, general}`，`ConfigStore` 启动整表读入内存、setter 后整文件 `fs::write` 覆写、写前不重读；几何落盘经 `ConfigSync::save_window_geometry`，退出再冲刷一次；全仓无单实例限制、无编号概念。写入纪律是本票的核心，不是顺手重构——所有现有写回路径都要收拢到同一条「重读—局部改—写回」通道。
