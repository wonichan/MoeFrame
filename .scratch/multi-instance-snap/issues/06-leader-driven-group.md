# 06: 领队驱动整组（方向关系属性树 / HDWP 子树搬运 / 拆组清属性）

**What to build:** 让贴合的相框真正按 PotPlayer 语义联动：吸附关系带方向（从属/基座，记为从属窗上的窗口属性），拖动开始时被拖进程算出自己的从属子树，拖动中由领队用 HDWP 把子树按同一增量原子搬走——拖基座带整树、拖从属先脱离再带自己的子树；Shift 独走与菜单脱离改为清属性。同时整段拆除路线 (b) 的轮询跟随引擎与抑制标记，接触派生降为存量接触临时成树与锚边邻居判定的辅助。

**Blocked by:** [05: WM_MOVING 实时磁吸](05-wm-moving-snap.md)

**Status:** ready-for-agent

## Acceptance criteria

代码项：

- [ ] 方向关系存储：从属窗以 Win32 窗口属性（SetProp/GetProp/RemoveProp）记基座 HWND，属性名定死并避免与工单 04「退出请求标记」等既有属性冲突；关系读写/清除收成宿主薄层 + 可测的纯判定（属性值解析、基座存活校验）。一窗至多一个基座；设属性只发生在工单 05 磁吸命中贴合时（对齐命中不成关系）与本票的存量接触临时成树。
- [ ] 子树计算（纯逻辑可测）：给定全量窗口的「从属→基座」关系表，算出任一窗口的从属子树（传递闭包）；环路防御（关系数据异常成环时不死循环、按断环处理），用例覆盖单链、三层树、一基座多从属、无关系空集、环。
- [ ] 整组搬运：WM_ENTERSIZEMOVE 时被拖进程读关系表算子树；WM_MOVING 每帧以被拖窗位移增量（与上帧拟拖/实际矩形之差，口径定死）用 BeginDeferWindowPos/DeferWindowPos/EndDeferWindowPos（SWP_NOACTIVATE | SWP_NOSIZE）搬子树，单帧原子提交；拖动结束（WM_EXITSIZEMOVE）收尾清状态。搬运只发生在被拖进程，伙伴进程拖动中不跑跟随逻辑。
- [ ] PotPlayer 分离语义：拖从属时，它在拖动开始先清自己的基座属性（脱离），只带自己的子树走，原基座及其余从属不动；拖基座带整棵子树。拖动中吸上新基座：被拖窗设属性成为其从属（原有子树并入，由后续拖基座时按新树联动）。三种情形的判定逻辑纯函数化并有测试（以关系表 + 被拖窗输入、期望的清/设属性与搬运集合输出）。
- [ ] 存量接触临时成树：启动后从未拖动过的已贴合窗口，拖动开始时按接触派生（工单 02 纯逻辑）把直接接触者临时视为被拖窗的从属参与本次搬运；临时关系在本次拖动内有效，拖动中若磁吸命中则按上一条转正为属性关系；临时成树的判定有测试（贴合者入树、对齐者不入、跨屏不入）。
- [ ] 拆组清属性：Shift+拖动——本次拖动不带子树且被拖窗清基座属性（拖动开始判定，采样 Shift 的时机沿工单 03 已落地的手势开始采样）；右键菜单「脱离吸附组」改为清本窗基座属性（位置不变；菜单项出现条件改为「本窗有基座属性或有直接接触」，定死并注明）；工单 03 的抑制标记机制整段拆除，其测试逐条交代去向。
- [ ] 卫生规则：拖动开始与磁吸求解前校验本窗基座属性——基座窗口已不存在（枚举不到/进程已退出）或两者已不接触（相对边间隙 > 吸附阈值）则清属性；校验为纯判定 + 薄宿主执行，有测试（基座消失、间隙超限、同屏变跨屏三种失效各一）。
- [ ] 拆除轮询跟随：库 snap_follow 的 FollowEngine/PollSchedule 与宿主轮询挂接整段拆除，静止零重绘口径回归到「无吸附专题轮询」的基线（帧尾唤醒裁决不再并入任何吸附轮询间隔）；被拆路径的旧测试逐条交代去向（删除/改写及理由记 Comments），测试总数对账不低于基线减去已交代的拆除数。
- [ ] 锚边变尺寸接关系树：工单 03 的锚边计算保留，邻居来源改按「属性关系（基座/直接从属）+ 直接接触」判定，不再按无方向连通分量；工单 03 锚边既有测试按新口径复核（改写处逐条记 Comments），与工单 06（切图溢出钳制）叠加顺序不变。
- [ ] 伙伴被外力移动的吸收：审计 geometry 观察路径——伙伴被 HDWP 搬走后，其进程的几何机不得把这次纯位置变化误判为用户手势（不触发比例校正、不抢写落盘几何）；按「位置变了、尺寸没变」自然吸收进观察与防抖落盘（沿落盘以实际观察为准的口径）。发现打架点在本票修掉并加回归测试；无打架点也要在 Comments 写明审计结论（观察了哪条路径、为何不打架）。
- [ ] 检查：`scripts/check.sh` 本体未运行（Windows 专用，本 VM 跑不了，不冒充）；替代口径全绿——Linux 测试副本 `cargo test --all-targets` 通过（增删逐项对账），Windows 目标 `cargo check --all-targets`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --all -- --check` 三项通过。

实机项（汇总进专题实机清单，返工收尾时重写对应条目）：

- [ ] 实机：三扇相框依次拖吸成链/树，拖基座（最先被吸靠的那扇）整组实时同移、贴合不散、无延迟追赶感。
- [ ] 实机：拖链中间/末端的从属窗，它先脱离、只带走它自己（及其从属），原组其余留在原地仍可整组拖动。
- [ ] 实机：Shift 拖动组内一扇，独自离开，其余成员纹丝不动；右键「脱离吸附组」后拖任意一边互不带动。
- [ ] 实机：重启程序后（关系不落盘）各窗回到落盘位置，直接拖已贴合的一扇，整组仍能一起动（存量接触临时成树）。
- [ ] 实机：把组员拖向另一块屏再拖回来，关系卫生规则不残留（不该联动的不会被陈旧关系拉走）。
- [ ] 实机：组内一扇开自动轮播切图变尺寸，共享边不动、邻居不被推走（锚边在新关系口径下仍成立）。

## Context

专题 spec 第 15 节与 ADR-0005 为本票口径来源。关键结构：协调权只在被拖进程手里——伙伴进程在别人拖动时不运行任何吸附逻辑，这是与旧路线 (b) 的根本区别，也是 Dormant 不对称、回声吞移、组图过期三类旧硬伤整类消失的原因。关系载体选窗口属性而非文件/注册表：跨进程可读、随窗口生灭、无落盘一致性问题；工单 04 已有「退出请求标记」属性的先例，命名与用法不要撞车。锚边变尺寸（工单 03）与级联/自启/同步（工单 01/04）的成果不在本票推翻范围。
