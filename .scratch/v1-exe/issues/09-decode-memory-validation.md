# 09: 图片解码与内存最小验证

**What to build:** 用独立验证程序实际显示和预加载图片，量出解码、缩放、释放及拒绝行为的资源边界，让用户据此确认可接受的峰值上限和图片限制，再进入正式图片加载实现。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 暂定保留 image，允许短暂全分辨率解码，缩到窗口物理像素需求后释放整图；填充按覆盖尺寸计算。验证不依赖完整相框，不与窗口能力验证捆绑。
- [ ] 测试普通 1080p、2K、4K、100MP 级图片，以及损坏图和伪装扩展名样本；包含适应、填充及下一张预加载的资源路径。
- [ ] 普通 1080p、2K、4K 图片正常显示，不能靠大量拒绝普通图片满足指标。合法但超限的大图允许拒绝，并记录路径和具体原因；坏图不崩溃、不卡死，仍可继续显示其他图片。
- [ ] 默认 480×320 窗口下，解码、缩放和下一张预加载完成后的稳定工作集 ≤50MB；连续轮播验证 1 小时无持续增长。
- [ ] 长期只保留当前图与下一张显示数据，不保留全分辨率历史或大缓存；记录全分辨率数据和切走图资源的释放情况。
- [ ] 每组结果记录实际构建与依赖版本、样本尺寸、逻辑及物理窗口尺寸、显示模式、稳定工作集、瞬时峰值和拒绝原因；用实际测量而非理论像素字节数作为证据。
- [ ] 分开报告稳定工作集和瞬时峰值，不自动将瞬时峰值套用 50MB，也不把 Limits 当作整个进程工作集硬上限。
- [ ] 根据实测提出具体 Limits 阈值与峰值上限建议，并拿到用户确认；不得使用未经确认的数值或库默认值充当产品安全线。
- [ ] 失败先排查重复缓冲、释放时机和限制设置；确认仍不达标后另开备选票，不自行更换解码器。未通过实测或未完成两项阈值确认时，本票不得标为完成。
- [ ] 留存后续正式程序可复测的样本说明与测量步骤；本票通过不能代替最终完整程序的性能验收。
