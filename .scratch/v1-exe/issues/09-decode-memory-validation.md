# 09: 图片解码与内存最小验证

**What to build:** 用独立验证程序实际显示和预加载图片，量出解码、缩放、释放及拒绝行为的资源边界，为后续正式图片加载实现提供实测依据。工单 09 不执行一小时轮播，也不提出或确认产品 Limits / 峰值上限；这些仍是 V1 正式图片加载前的项目级门槛。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 暂定保留 image，允许短暂全分辨率解码，缩到窗口物理像素需求后释放整图；填充按覆盖尺寸计算。验证不依赖完整相框，不与窗口能力验证捆绑。
- [ ] 测试普通 1080p、2K、4K、100MP 级图片，以及损坏图和伪装扩展名样本；包含适应、填充及下一张预加载的资源路径。
- [ ] 普通 1080p、2K、4K 图片正常显示，不能靠大量拒绝普通图片满足指标。合法但超限的大图允许拒绝，并记录路径和具体原因；坏图不崩溃、不卡死，仍可继续显示其他图片。
- [ ] 默认 480×320 窗口下，解码、缩放和下一张预加载完成后的稳定工作集 <100 MB。工单 09 不要求连续轮播 1 小时。
- [ ] 长期只保留当前图与下一张显示数据，不保留全分辨率历史或大缓存；记录全分辨率数据和切走图资源的释放情况。
- [ ] 每组结果记录实际构建与依赖版本、样本尺寸、逻辑及物理窗口尺寸、显示模式、稳定工作集、瞬时峰值和拒绝原因；用实际测量而非理论像素字节数作为证据。
- [ ] 分开报告稳定工作集和瞬时峰值，不自动将瞬时峰值套用 50MB，也不把 Limits 当作整个进程工作集硬上限。
- [ ] 失败先排查重复缓冲、释放时机和限制设置；确认仍不达标后另开备选票，不自行更换解码器。其他实测验收未通过时，本票不得标为完成。
- [ ] 留存后续正式程序可复测的样本说明与测量步骤；本票通过不能代替最终完整程序的性能验收。

## Context

父规格：[V1 可运行程序规格](../spec.md)，重点为后台加载、资源边界与解码最小验证。

原[全分辨率解码](07-full-res-decode.md)关闭的是路线决定，不是实测或验收。本票与 [08: 无边框窗口最小验证](08-window-validation.md)可独立开始，不修改原路线票。
