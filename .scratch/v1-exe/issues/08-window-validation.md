# 08: 无边框窗口最小验证

**What to build:** 提供独立的窗口验证程序、操作清单和诊断日志，让用户在本机确认相框所需的窗口能力确实可用，再开始正式窗口实现。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 沿用 Rust 与 eframe/egui，只验证窗口能力，不实现图片解码、轮播、托盘、配置恢复或宽高比锁定。
- [ ] 窗口无标题栏、无系统边框；四边和四角均可反复放大、缩小，最小尺寸为 120×120 逻辑尺寸。
- [ ] 内容区可拖动，边缘缩放不误触发窗口移动；默认不置顶，创建时不抢焦点。
- [ ] 最大化时不发起边缘缩放；恢复普通大小后，内容区移动与八方向缩放仍然可用。不由此给正式产品新增最大化按钮。
- [ ] 提供逐项操作清单，记录实际系统、构建与依赖版本、DPI、逻辑尺寸和物理客户区尺寸，保留可追溯的诊断结果。
- [ ] 按既定路线先在用户本机 Windows 11 x64 Build 26100 操作；实际环境有差异时如实记录，不将未测环境写成通过。
- [ ] 用户实际完成拖动、缩放等操作并确认结果。编译成功、截图或 API 成功返回不能替代实机操作；未操作项保持未验证。
- [ ] 本机通过只解除正式窗口实现的前置门禁；Windows 10、混合 DPI 双屏等未测环境仍标明未验证。
- [ ] 失败时先排查调用方式并记录结果；确认仍不满足要求后另开备选票，不自行更换 GUI 框架。未通过或未收到用户确认时，本票不得标为完成。
