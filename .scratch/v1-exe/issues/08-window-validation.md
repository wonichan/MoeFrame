# 08: 无边框窗口最小验证

**What to build:** 提供独立的窗口验证程序、操作清单和诊断日志，让用户在本机确认相框所需的窗口能力确实可用，再开始正式窗口实现。

**Blocked by:** None (can start immediately).

**Status:** resolved

## Acceptance criteria

- [x] 沿用 Rust 与 eframe/egui，只验证窗口能力，不实现图片解码、轮播、托盘、配置恢复或宽高比锁定。
- [x] 窗口无标题栏、无系统边框；四边和四角均可反复放大、缩小，最小尺寸为 120×120 逻辑尺寸。（用户 2026-11-17 实机确认；最小读数 188×183.3 逻辑点，120×120 下限未捕获快照）
- [x] 内容区可拖动，边缘缩放不误触发窗口移动；默认不置顶，创建时不抢焦点。（用户实机确认；日志 topmost=false、创建时前台与 focus 均不在验证窗口）
- [x] 最大化时不发起边缘缩放；恢复普通大小后，内容区移动与八方向缩放仍然可用。不由此给正式产品新增最大化按钮。（用户实机确认）
- [x] 提供逐项操作清单，记录实际系统、构建与依赖版本、DPI、逻辑尺寸和物理客户区尺寸，保留可追溯的诊断结果。（见 [操作清单](../../../docs/window-validation.md)）
- [x] 按既定路线先在用户本机操作；实际为 Windows 11 x64 Build 26200、缩放 150%，与计划的 26100 不同并已如实记录，未测环境未写成通过。
- [x] 用户 2026-11-17 实际完成拖动、缩放等操作并确认结果；编译成功与日志不作为替代。
- [x] 本机通过只解除正式窗口实现的前置门禁；Windows 10、100% 缩放与混合 DPI 双屏仍标明未验证。
- [x] 无需排查失败调用；未另开备选票，未更换 GUI 框架。
