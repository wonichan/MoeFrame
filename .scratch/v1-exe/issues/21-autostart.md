# 21: 开机自启与失败回滚

**What to build:** 用户从相框菜单或设置窗控制开机自启，界面、已保存配置与系统实际状态一致；设置失败时保留原状态且不弹窗打扰。

**Blocked by:** [18: 设置窗：即时设置与独立生命周期](18-settings-window.md)。

**Status:** needs-info

## Acceptance criteria

- [x] 相框菜单和设置窗提供有效的开机自启开关，两处反映同一真实状态，改动立即执行并在成功后保存。（单一状态源 AutostartSync，两处都读它渲染、都走同一 apply_autostart；先写系统成功才保存镜像。如实注：镜像保存本身失败时不回滚系统状态——界面与系统仍一致，镜像靠下次启动对齐自愈，本会话内三方一致性短暂破缺）
- [x] 使用父规格指定的当前用户 Run 项和应用项名，不写系统级自启项；除该项外，业务配置仍只使用已有配置契约，不转移到注册表。（HKCU Run 的 MoeFrame 项，常量与规格第 10 节一致；只有 RegAutostartStore 碰注册表且只动这一个值，禁用不触碰其他值）
- [x] 启动读取及用户切换时，开关不只反映一个过时配置布尔值，须与实际系统自启状态一致。（启动以实际状态对齐并回写镜像，读失败才退回镜像；Run 键/值不存在是确定的未启用、值在但类型不对经原始值判存在。如实注：运行中外部改动不重读，要到重启才纠正——工单字面只约束启动与切换两个时点）
- [x] 写入或移除失败时，开关与配置回到操作前状态，不伪报成功、不弹窗；合法的其他设置不受影响。（apply 先写系统、失败返回 None 且状态不动，两处 UI 从状态渲染自然回原值；全路径无弹窗；自启路径不经核心、不动其他配置字段。镜像保存失败的形态见标准 1 注）
- [x] 启动目标正确指向实际程序，程序路径含中文、空格或特殊字符时仍正确；不因此引入安装器、后台服务或联网行为。（每次切换按 current_exe 现取路径、整体加引号，纯函数测试覆盖中文+空格路径；winreg 为本地 API）
- [x] 自启操作不改变相框显示或隐藏、设置窗生命周期、当前图、轮播暂停状态及间隔计时。（自启路径不派发任何核心意图；设置窗点自启引起的草稿失焦走工单 19 的普通失焦提交，非本票扰动）
- [x] 应用行为测试通过可控系统操作结果验证成功同步、失败回滚、同一状态的菜单与设置窗展示及配置保存；mock 仅证明应用行为，不代替真实系统验证。（替身测试覆盖对齐/回写/退镜像/成功同步/失败回滚/命令引号，配置镜像真实文件往返；如实注：双入口展示与「成功后保存」完整链在 Windows-only 宿主内无自动化，靠单一状态源的结构保证，真实系统验证归标准 8）
- [ ] 明确实机执行人，在 Windows 验证启用、禁用、实际自启目标及可复现的失败路径，记录系统状态与界面结果；测试后恢复测试前的自启状态，不覆盖用户已有无关项。（未做：并入仓库根目录 real-machine-check-10-21.md 的工单 21 一节，本票因此 needs-info）
