# 19: 路径与秒数编辑：草稿、提交和校验

**What to build:** 用户在设置窗编辑文件夹路径或自定义秒数时，不会因打字触发扫描或计时变化；提交、关闭、重新扫描及菜单改值各有明确结果，输入失误不会抹掉有效间隔。

**Blocked by:** [16: 手动重扫后继续当前轮](16-manual-rescan.md)、[18: 设置窗：即时设置与独立生命周期](18-settings-window.md)。

**Status:** resolved

## Acceptance criteria

- [x] 设置窗补齐路径框、重新扫描按钮及自定义秒数框，不增加独立文件夹选择器；菜单选择文件夹仍是原有入口。（三控件已补齐，无窗口内选择器）
- [x] 路径和秒数输入期间只形成草稿，不扫描、不改变计时，也不将中间文字写成已生效配置。（草稿只是宿主字符串，打字路径上无任何派发/写盘；结算语义有库层测试）
- [x] 失焦或回车时去掉首尾空白后提交；点击相框或设置窗其他普通控件算失焦，回车提交后焦点仍在输入框。（结算函数统一 trim；窗内失焦经焦点跟踪、点相框经设置窗视口系统焦点采样一路汇入同一延迟结算；回车立即结算并 request_focus 抢回焦点——焦点是否真留住待实机标准 12）
- [x] 点击重新扫描只扫描已生效路径，不提交路径或秒数草稿，不能由该按钮触发的失焦绕过此例外。（失焦延迟一帧结算，重扫点击在结算前否决待结算并清当帧失焦记录，同帧/隔帧两种排布均成立，Spec 审查核对）
- [x] 关闭按钮、设置窗 Alt+F4 或 Esc 丢弃未提交文字，不借关闭导致的失焦提交；重新打开显示实际生效值。（关闭分支优先级最高、清待结算；重开时 request_settings 强制重播种）
- [x] 菜单或预设修改同一项时，丢弃该项未提交草稿并显示生效值；菜单选择文件夹同样覆盖路径草稿。其他项不被无故改写。（每帧基线比对重播种 + 结算入口二次比对双保险，按字段独立，结算层测试覆盖作废分支）
- [x] 秒数仅接受普通十进制整数，范围 3 到 99999999。空白、小数或解析失败保留上次有效值，不回退 30；可解析但越界的整数钳制到边界，并显示提交结果。（parse_interval_draft 边界矩阵测试含超 i64 位数按符号钳制；结算返回显示文字即钳制结果）
- [x] 间隔有效值变化才保存并重新计满；同值不重计、不重写。暂停中提交只记录新值，恢复时计满；模式或显示方式切换不附带重计。（同值在结算层即 Noop 不派发；派发走既有 IntervalSelected，工单 11 核心测试守重计/暂停规则）
- [x] 无效、空白、指向文件或不存在的文件夹路径保留提交文本，图库进入空状态，不反复弹窗；有效路径提交后真正更新图库，沿用既定增删和续播规则。（结算层照常原样提交无效文本，核心保留该文件夹、扫描落空进 Empty，全程无弹窗；有效路径走 FolderPicked 既定规则）
- [x] 输入框解析失败与配置读取修复保持两套规则，不将输入框错误改成默认 30，也不让配置中的坏值原样继续生效。（ADR-0003：parse_interval_draft 与配置修复路径分开实现、互不调用，测试名即此不变量）
- [x] 通过应用行为入口和真实临时目录、配置文件测试打字不生效、回车、普通失焦、重扫例外、全部关闭路径、菜单覆盖、无效路径及秒数边界；用可控时间断言计时，而非控件私有状态。（可纯化的部分已测满：结算决策七项（提交/同值/作废/无效保留）+ 解析边界矩阵 + 派发后行为由工单 11/13/16 既有核心与真实文件测试守；纯 UI 事件部分——回车焦点、失焦触发时机——属控件行为，归实机标准 12，不以 mock 冒充）
- [ ] 实际操作验证回车保留焦点、关闭不误提交及重新扫描不提交草稿，记录结果。（未做：并入仓库根目录 real-machine-check-10-19.md 的工单 19 一节，另点名验「点相框算失焦」，本票因此 needs-info）
