# 15: 点击、双击、拖动分界与当前图操作

**What to build:** 用户既能拖动相框，又能用侧边点击切换、双击打开瞄准的原图和右键操作当前图，互相之间不误触，动画期间也保持明确的操作结果。

**Blocked by:** [14: 方向正确、连点不乱的滑动切换](14-slide-transitions.md)。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 采用 Windows 系统拖动阈值及系统双击时间、距离，不写死另一套值。移动超过拖动阈值后成为拖动，松开不切换；边缘缩放不误触内容移动或点击。
- [ ] 左、右各 20% 区域点击分别为上一张、下一张，中间 60% 单击无动作；侧边单击等待系统双击窗口结束才成立。
- [ ] 双击要求两次按下均未成为拖动，且在系统双击时间和距离内；双击本身不切换，用系统默认看图器打开第一下按下时相框正在显示的原图，而非即将进入的目标图。
- [ ] 等待第二下时，新按下超出双击距离或移动超过拖动阈值，先把第一下按单击结算，新按下重新判断，不与第一下组成双击。
- [ ] 右键只打开菜单并取消未完成左键动作，含等待双击的单击；若正在拖动，先恢复到该次按下时的位置，再打开菜单。已在播放的动画不取消。
- [ ] 动画中拖动只移动相框，不切换、不打断动画；双击不产生切换；已经成立的导航意图仍遵循只保留最后一次的规则。
- [ ] 相框菜单补齐打开当前原图、打开其所在文件夹和复制图片路径；目标是当前成功显示的原图路径，中文、空格和特殊字符路径均正确。
- [ ] 通过应用行为入口测试单击等待、双击目标固定、超距重新判定、拖动不切换、右键取消及位置回滚、动画中手势和最后意图，使用可控时间而非真实 sleep。
- [ ] 用户或明确的实机执行人实际验证拖动、系统双击、右键与动画冲突，以及默认看图器、文件夹和剪贴板操作；mock、截图或 API 成功不能替代实际结果，未验证项不标通过。
