# 23: 端到端验收与最终交付

**What to build:** 用户拿到真正可长期使用的免安装 release 相框、源码和简短说明；第 10 节及规格的必需行为均有真实验收记录，尚未验证的环境被明确区分，而不是把编译成功当成交付完成。

**Blocked by:** [22: 完整程序的轻量 release 达标](22-release-resource-budgets.md)。

**Status:** ready-for-human

## Acceptance criteria

- [ ] 准备需求第 10 节与父规格最终验收表的逐项记录，明确需要人工操作项目的执行人；没有实际操作的项目不勾选通过。
- [ ] 用至少 100 张真实图片、包含子目录和中文路径的图库验证完整流程，覆盖各必需格式和 GIF 第一帧、横竖图适应及填充、正常轮播和手动重新扫描。
- [ ] 验证自然序循环、随机 N 个新选择无重复、轮间避让与单图边界、真实历史回看、回到最新图后继续未看、跨启动当前图与本轮进度恢复，区别恢复当前图这个防重复例外。
- [ ] 验证手动重计、暂停、六档及自定义间隔、同值不重计、方向正确的滑动、连续意图合并、慢图不白屏，以及点击、双击、拖动、右键冲突的最终结果。
- [ ] 在 Windows 实际操作拖动、八方向缩放、宽高比锁定、位置尺寸恢复和可用的多屏 DPI 路径；确认副屏移除或离屏恢复后可找回相框，不把最小验证结果冒充完整产品验收。
- [ ] 实际验证相框关闭后进程与轮播继续、托盘隐藏和唤回、明确退出、设置窗独立生命周期、草稿提交与关闭丢弃、菜单同步、自启实际生效及失败回滚。
- [ ] 验证损坏图、伪装扩展名、超限图片、删除当前文件、空或无效目录、配置缺失和局部损坏，不崩溃、不卡死，继续寻找可显示图片或提供可操作空状态；日志记录跳过路径和超限原因。
- [ ] 核对 [22](22-release-resource-budgets.md)的完整 release 证据确实属于本次交付构建，覆盖稳定内存、确认后的峰值、1 小时轮播、CPU、体积、冷启动、10,000 张路径规模及资源释放；构建变化后相关结果需复测。
- [ ] 全部核心及应用行为测试通过，包括 playlist 的自然序、洗牌袋、历史、恢复和图库增删；以 `cargo test` 的实际通过结果留证，不以测试数量或 mock 成功替代行为验收。
- [ ] 交付源码仓库、实际 release `MoeFrame.exe` 和简短 README；程序可免安装运行，不将仅能弹窗的骨架或 debug 文件作为最终交付。
- [ ] README 简述首次选择文件夹、导航、轮播、适应或填充、关闭与退出、托盘、自启、配置和日志位置；说明自定义间隔为 3 到 99999999 秒，以及悬停暂停、动画类型、显示文件名三个保留键尚未生效。
- [ ] 按 ADR-0003 补充需求第 6 节配置注释中的三个 P1 键及新间隔范围说明，不借此改写 FR-401、FR-504 或其他需求正文；父规格、路线图及旧决定票不因此重写或关闭。
- [ ] 验收记录包含实际构建、系统版本、显示器与 DPI、样本和操作结果；Windows 10、混合 DPI 双屏等未测环境保持未验证，不宣称完整兼容已通过。必需项未通过或人工结果缺失时，本票不得标为完成。
- [ ] 本次交付不增加悬停条、悬停暂停、文件名显示、其他动画、自动扫描、单实例、联网、多相框等范围外能力，不以缺少 P1 阻挡符合既定完成线的交付。
