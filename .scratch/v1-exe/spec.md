# V1 可运行程序规格

Status: ready-for-agent

本规格汇总「V1 可运行程序」路线图及已确认决定。此状态表示可以从前置最小验证开始执行，不表示窗口能力、解码方案或 V1 已验收通过。它只适用于本规格，不改变路线图及其子票的标签、类型或状态。

## Problem Statement

用户拥有数千张本地动漫壁纸与插画，逐张打开浏览成本高，大量收藏长期没有被看见。用户需要在工作时顺便欣赏这些收藏，而不是替换全屏壁纸、配置复杂皮肤，或者运行带来明显资源占用和打扰的软件。

目前仓库只有需求、领域词汇、ADR 和路线决定，没有可运行的相框或已有测试。仅交付决策路线、能弹窗的骨架或 debug 二进制，都不能满足用户需求。用户最终需要一个能够长期常驻、重启后续播、可从托盘管理，并通过需求文档第 10 节验收的 release 程序，以及简短使用说明。

## Solution

交付一个 Windows 10/11 x86_64 本地桌面相框：首次选择图片文件夹后，递归收集图片路径，在可自由移动、缩放的普通无边框窗口中自动轮播。相框支持顺序与随机两种播放模式、上一张与下一张、方向正确的滑动动画、适应与填充、菜单、托盘和独立设置窗。

配置和窗口状态自动保存；随机模式分别保存本轮进度与历史，重启先恢复当前图。关闭相框只隐藏到托盘，退出才结束进程。程序不联网、不上传、不投放广告，不把图片集合全量解码或缓存在内存中。

先分别完成窗口能力和解码内存的独立最小验证，拿到对应通过结果后，才进入对应正式实现。最终交付源码仓库、免安装的 release `MoeFrame.exe` 和简短 README；P1 不阻挡完成，但不能因此省略手动重新扫描、必需的设置窗或已明确的第 10 节测试。

## User Stories

### 启动与图库

1. 作为 Windows 桌面用户，我希望直接运行免安装的相框，以便无需配置运行环境就能欣赏收藏。
2. 作为首次使用者，我希望启动时只需选择一个图片文件夹，以便用默认设置开始轮播。
3. 作为暂时不想选择文件夹的用户，我希望取消选择后看到空状态和「右键选择文件夹」提示，以便稍后继续而不被反复弹窗打扰。
4. 作为把收藏分散在子文件夹中的用户，我希望图库递归包含根文件夹下的图片，以便不必整理成单层目录。
5. 作为拥有不同图片格式的用户，我希望相框支持大小写不敏感的 jpg、jpeg、png、webp、bmp 扩展名，以便直接使用现有收藏。
6. 作为拥有 GIF 收藏的用户，我希望 V1 至少显示 GIF 的第一帧，以便这些文件不会仅因是动图格式而完全不可见。
7. 作为中文 Windows 用户，我希望中文、空格和特殊字符路径正常工作，以便不必重命名收藏或移动文件夹。
8. 作为拥有大量收藏的用户，我希望扫描只枚举路径、不预解码全部图片，以便启动和常驻资源占用不随图片总像素量膨胀。
9. 作为用户，我希望从相框菜单选择新的图片文件夹，以便更换收藏来源。
10. 作为用户，我希望从菜单或设置窗手动重新扫描，以便不重启程序就能主动更新图库。
11. 作为输入无效路径或使用空文件夹的用户，我希望相框显示空状态且保持可操作，以便修正路径而不是处理崩溃或重复提示。

### 播放序列、历史与恢复

12. 作为用户，我希望顺序模式按完整路径自然排序循环显示，以便路径中的连续数字按数值而不是字典序排列。
13. 作为用户，我希望自然排序的非数字部分按 Unicode 码点比较，以便排序规则明确且不依赖拼音。
14. 作为用户，我希望随机模式一轮内的新选择不重复，以便在重复之前看遍当前图库。
15. 作为用户，我希望图库至少两张时，新一轮第一张不同于上一轮最后成功显示的图，以便轮与轮之间不立即重复。
16. 作为只有一张可用图片的用户，我希望它保持显示，以便防重复规则不会导致无图可看。
17. 作为随机模式用户，我希望「上一张」回到实际看过的图，以便回看刚刚错过的收藏。
18. 作为正在回看的用户，我希望下一张和轮播先沿历史回到最新图，再继续未看图片，以便回看不打乱本轮进度。
19. 作为重启程序的用户，我希望先恢复退出前正在显示的图，以便相框能从上次状态继续。
20. 作为随机模式用户，我希望本轮进度跨启动保存，以便重启后的新选择不会重新抽到本轮已经看过的图。
21. 作为随机模式用户，我希望历史跨启动保留最近 512 条，以便重启后仍可回看，同时避免历史无限增长。
22. 作为删除过旧收藏的用户，我希望上一张自动跳过历史中已经不在图库的路径，以便仍能回到有效图片。
23. 作为用户，我希望当前图已不在图库时按既定恢复规则选择有效图片并更新状态，以便启动不会卡在失效路径。
24. 作为用户，我希望读取或解码失败的图片不进入本轮进度与历史，以便「看过」只表示实际成功显示过。
25. 作为手动重新扫描后的用户，我希望已删除路径从后续播放中剔除、新增路径视为本轮未看，以便当前一轮不因图库增删被无故重置。

### 相框窗口与显示

26. 作为用户，我希望首次相框为 480×320、位于屏幕右下角内缩 24px，以便开箱即用且不占据工作区中央。
27. 作为用户，我希望相框无标题栏、无系统边框、默认不置顶且创建时不抢焦点，以便它安静地常驻桌面。
28. 作为用户，我希望从图片任意位置拖动相框，以便把它放在合适位置而不需要标题栏。
29. 作为用户，我希望拖动四边或四角缩放，并且尺寸不低于 120×120，以便灵活调整而不把窗口缩到无法使用。
30. 作为用户，我希望可选地锁住开启那一刻的窗口宽高比，以便缩放时保持当前形状而非强制恢复默认比例。
31. 作为用户，我希望适应模式完整显示横图和竖图、保持比例，空白区默认纯黑，以便看清整张图且不变形。
32. 作为用户，我希望填充模式按比例铺满相框并居中裁剪，以便获得无黑边的展示。
33. 作为用户，我希望图片几乎贴边、内边距默认不超过 4px，以便相框不会用宽边框和大留白遮占图片空间。
34. 作为高 DPI 或多显示器用户，我希望图片按所在显示器的窗口物理像素尺寸缩放，以便跨屏后清晰度和尺寸正确。
35. 作为用户，我希望重启后恢复窗口位置、大小和设置，以便不用每次重新摆放相框。
36. 作为拔掉副屏的用户，我希望恢复位置自动回到主屏可见区域，以便不会丢失相框。
37. 作为用户，我希望恢复默认位置与大小能立即生效并保存，以便快速找回相框；相框隐藏时也能借此显示出来。

### 轮播、导航与手势

38. 作为用户，我希望默认每 30 秒自动切换，并可选六档预设或输入 3 到 99999999 的整数秒，以便按自己的节奏欣赏收藏。
39. 作为用户，我希望手动切换后重新计满一个间隔，以便刚切到的图片不会马上被自动切走。
40. 作为用户，我希望暂停停止自动轮播但保留手动切换，以便停留细看或继续主动浏览。
41. 作为聚焦相框的用户，我希望方向键切换、空格播放或暂停，以便不必打开菜单。
42. 作为用户，我希望滚轮向上回到上一张、向下切到下一张，以便快速浏览。
43. 作为用户，我希望点击左、右各 20% 区域分别触发上一张、下一张，中间单击不切换，以便有明确的鼠标操作区域。
44. 作为用户，我希望拖动结束不被当成点击，以便移动相框时不会误切换。
45. 作为用户，我希望双击打开第一下按下时正在显示的原图而不切换，以便系统看图器打开的正是我瞄准的收藏。
46. 作为用户，我希望侧边单击等待系统双击窗口结束才切换，以便双击不会先误切到另一张。
47. 作为用户，我希望右键只打开菜单并取消未完成的左键动作，以便菜单操作不会混入拖动或切换。
48. 作为用户，我希望下一张从右滑入、上一张从左滑入，采用约 300ms 的 ease-out 滑动，以便方向清楚且切换自然。
49. 作为连续操作的用户，我希望动画期间的新切换意图只保留最后一次、不并行播放动画，以便连点不乱序。
50. 作为用户，我希望目标图未就绪时保留当前图、不闪白，以便后台解码不会破坏观感。

### 菜单、托盘与系统操作

51. 作为用户，我希望右键菜单能控制导航、播放、模式、间隔和显示方式，以便不依赖额外控制条。
52. 作为用户，我希望能打开当前原图、打开其所在文件夹和复制路径，以便进一步查看或管理收藏。
53. 作为用户，我希望系统托盘图标常驻、左键切换相框显示与隐藏，以便快速收起或找回相框。
54. 作为用户，我希望托盘菜单在相框隐藏时仍能控制播放、导航、设置和退出，以便不用先显示相框。
55. 作为用户，我希望 Alt+F4 等关闭相框的操作只隐藏窗口、进程和轮播继续，以便不会误退出常驻程序。
56. 作为用户，我希望只有明确选择菜单或托盘的「退出」才结束进程，以便关闭与退出的含义稳定。
57. 作为用户，我希望开机自启开关与实际系统状态一致，以便知道相框是否会随下次登录启动。
58. 作为用户，我希望开机自启写入失败时开关和配置回到原值且不弹窗，以便界面不谎报成功，也不打扰工作。

### 设置与持久化

59. 作为用户，我希望菜单和托盘打开同一块非模态设置窗，已打开时带到前台，以便不产生多个互相冲突的设置副本。
60. 作为用户，我希望设置窗只提供本次真正生效的控件，以便不会看到无效的悬停暂停、动画类型或显示文件名开关。
61. 作为用户，我希望单选、开关和间隔预设立即生效、立即保存，并与菜单勾选同步，以便无需确定或取消。
62. 作为编辑路径和秒数的用户，我希望打字期间不扫描、不改计时，失焦或回车才提交，以便中间输入不会触发副作用。
63. 作为用户，我希望关闭设置窗时丢弃尚未提交的文字，以便关闭按钮、Alt+F4 或 Esc 不会意外保存草稿。
64. 作为用户，我希望点击重新扫描只扫描已提交路径，以便它不意外提交尚未确认的文字。
65. 作为用户，我希望菜单或预设改动同一项后覆盖输入框内未提交草稿，以便界面始终反映实际生效值。
66. 作为输入非法秒数的用户，我希望空白、小数或解析失败保留上次有效间隔，越界整数钳制到允许范围，以便输入失误不重置我的节奏。
67. 作为用户，我希望只在间隔有效值变化时重新计时，以便重复选择相同值不会延长等待。
68. 作为用户，我希望关闭设置窗不影响相框、轮播或进程，相框隐藏时打开设置窗也不自动唤出相框，以便两个窗口职责独立。
69. 作为用户，我希望配置损坏或字段缺失时安全修复并写回，能保留的合法设置不被抹掉，以便不会因局部错误丢失全部偏好。
70. 作为手动编辑配置的用户，我希望合法值在重启后保留，并清楚知道三个尚未生效的 P1 键，以便不会误以为它们已经控制行为。

### 资源、安全与交付

71. 作为用户，我希望图片读取和解码在后台进行，以便拖动、菜单和动画不被图片加载阻塞。
72. 作为用户，我希望长期只保留当前图与下一张的显示数据，切换结束释放旧图资源，以便相框保持轻量。
73. 作为用户，我希望损坏图、伪装扩展名文件和过大图片被安全跳过并记录路径，以便混入异常文件不会使相框崩溃或卡死。
74. 作为用户，我希望普通 1080p、2K、4K 图片正常显示，以便程序不会靠拒绝常见收藏来满足内存指标。
75. 作为用户，我希望大图解码峰值有实测和明确上限，以便短暂全分辨率解码不会变成无边界内存风险。
76. 作为用户，我希望默认窗口稳定工作集不超过 80MB、静止平均单核 CPU 小于 1%，并且轮播一小时不持续增长，以便能长期常驻。
77. 作为用户，我希望 release 程序不超过 15MB，普通冷启动到第一张图小于 1 秒，以便程序轻巧且响应快。
78. 作为重视隐私的用户，我希望程序只读本地收藏、不联网和不遥测，以便图片与使用行为不离开本机。
79. 作为用户，我希望拿到真实 release 程序、源码和说明，并能查到实机验收结果及未验证环境，以便分清可用交付与未经验证的承诺。
80. 作为后续维护者，我希望播放核心先有行为测试，并能运行全部核心单测，以便修改时不破坏随机防重复、历史和图库增删规则。

## Implementation Decisions

### 1. 范围、技术与执行门禁

- 以需求文档的 P0 为功能基线、以第 10 节为完成线，同时应用三个已接受 ADR 及窗口、解码验证票的明确覆盖。设置窗中的 P1 控件、悬停条按钮等交叉提及，不把对应 P1 功能升格为本次必做。
- 使用 Rust stable、edition 2021 或更新版本，GUI 沿用 eframe/egui。禁止 WebView、WorkerW 嵌入与任何网络请求。Windows 专有操作隔离于业务逻辑之外，不实际适配其他平台。
- 形成相框应用协调、图库扫描、播放序列与历史、后台图片加载、配置、菜单与托盘、开机自启等职责。需求中的模块划分是参考，不把文件布局或私有接口锁成产品契约；不顺手实现单实例或其他 P1。
- 依赖限于需求列出的类别，新增重型依赖须说明理由。release 开启 strip 和 LTO，交付单个免安装程序，不以 debug 构建替代。
- 窗口最小验证与解码最小验证相互独立。只有各自验证通过，才能进入对应正式实现；不得让整个产品先写完再补前置验证。失败先排查调用、缓冲重复、释放时机和限制设置，确认路线仍不达标后另开备选票，不自行更换框架或解码器。
- 本规格不预切里程碑或新增一批实施票。先执行已有验证路线，再按结果推进正式实现；源码与单测通过不等于实机验收通过。

### 2. 图库与无图状态

- 单个根文件夹，固定递归扫描；图库只保存路径，不预加载或预解码所有图片。支持 jpg、jpeg、png、webp、bmp，扩展名大小写不敏感；GIF 只显示第一帧，avif 不在完成线。
- 首次无配置只引导选择一次；取消后进入空状态并提示右键选择文件夹。空图库和无效文件夹不崩溃、不反复弹窗。路径包含中文、空格和特殊字符时，扫描、加载、配置及系统操作均须正常。
- 菜单选择文件夹与菜单、设置窗的手动重新扫描属于必做；定时重扫和文件系统监听不做。手动重新扫描更新图库时，沿用已经确认的播放规则，不打断仍有效的当前图。
- 加载失败、已删除或超过限制的路径继续跳过。跳过坏图须记录路径；超限同时记录原因。不得在无可显示图片时无限忙循环或白屏闪烁，必须保留可操作的无图状态。

### 3. 播放序列、本轮进度与历史

- 顺序模式按完整路径自然排序：连续数字按数值比较，其余部分按 Unicode 码点比较，不按拼音；末尾循环回开头。启动时定位当前图；当前图缺失时，取自然排序中该路径之后的下一张，必要时循环寻找可加载图片。
- 随机模式用洗牌袋生成播放序列；本轮的新选择只来自未看路径。当前图库全部看完才开启新一轮；图库至少两张时，新一轮第一张避开上一轮最后成功显示的图。只有一张时保持显示，不应用防重复和轮间避让。
- 本轮进度与历史是两份独立状态。前者记录本轮成功显示过的路径，后者按成功显示顺序保存最近 512 条；二者跨启动保留，只存路径，不存像素。不持久化洗牌袋，不承诺重启后未看图片的随机顺序完全复现。
- 当前图仍在图库时，重启先恢复它；恢复当前图是防重复例外，不将轮间避让套到启动。随后按保存的本轮进度重新组织未看部分。
- 上一张按实际历史回看，跳过已经不在图库的路径；回看不修改本轮进度。之后下一张或轮播先沿历史回到最新图，再继续本轮未看路径。
- 只有成功显示才允许提交当前图片路径、本轮进度和历史变化；候选图、读取失败、解码失败和缺失路径不冒充已经看过。不得由预加载提前记账。
- 随机模式当前图已不在图库时，清空旧本轮进度，对当前图库开始新一轮并显示首个可加载图片，成功后更新当前图。缺失的旧路径不追加为新历史。
- 图库变化时，删除路径从本轮进度及后续播放剔除，新增路径属于本轮未看。仍有未看旧路径时继续当前轮，不因增删整轮重洗。当前图片路径、本轮进度或历史字段损坏时，分别丢弃损坏字段并按缺失处理，不因一个坏字段抹掉其他合法设置。

### 4. 相框窗口、缩放与手势

- 普通无边框相框，无标题栏、无系统边框；默认 480×320，首次位于屏幕右下角内缩 24px，默认不置顶、创建时不抢焦点。最小尺寸 120×120 为逻辑尺寸，不能混同窗口物理像素尺寸。
- 图片区域可拖动；四边、四角可缩放。边缘缩放不误触发内容移动。宽高比锁定默认关闭，打开时锁住当时比例，不固定为默认比例；保持比例也不得把任一边缩到 120 以下。锁定不改变适应或填充，也不加入右键菜单。
- 适应完整显示整图且保持比例，空白区默认纯黑；填充按比例铺满并居中裁剪。禁止 Stretch。内边距默认不超过 4px，不实现宽边框、大留白或额外视觉装饰；纯黑的适应留白与不必要的内边距分开判断。
- 启用 per-monitor DPI 感知，按窗口物理像素需求生成显示数据；填充按覆盖尺寸计算。恢复到已拔除显示器范围之外时钳制回主屏可见区域。
- 左键移动超过 Windows 系统拖动阈值后成为拖动，松开不切换；未超过阈值的按下、松开才进入点击判定。左、右各 20% 为导航区，中间 60% 单击无动作。
- 双击采用系统双击时间与距离，要求两次按下均未变成拖动。侧边单击等待双击窗口结束才成立；双击本身不切换，用系统默认看图器打开第一下按下时相框正在显示的图，而非动画即将进入的目标图。
- 等待第二下时，新按下超出系统双击距离，或移动超过系统拖动阈值，则先把第一下按单击结算；新按下重新判断，不再与第一下组成双击。
- 右键只打开菜单并取消未完成的左键动作，包括等待双击的单击；若正在拖动，先回到该次按下时的位置再打开菜单。右键不取消已经播放的动画。
- 动画中拖动只移动相框，不切换、不打断动画；双击也不产生切换。已经成立的导航意图仍进入「只保留最后一次」规则，不启动并行动画。

### 5. 轮播、动画与后台加载

- 默认随机模式、30 秒间隔。菜单保留 10 秒、30 秒、1 分钟、5 分钟、10 分钟、30 分钟六档；自定义为 3 到 99999999 的整数秒。此范围覆盖原 FR-401 的 5 到 3600。
- 聚焦相框时，左右方向键导航、空格播放或暂停；滚轮上为上一张、下为下一张；侧边点击、右键菜单和托盘导航共用播放行为。暂停停止自动轮播，手动导航仍可用；手动切换后重新计满间隔。
- 有效间隔变化时，从生效时刻重新计满；相同值不重计、不重写。暂停中修改只记录新值，恢复播放时再计满；切换播放模式、适应或填充不额外重置计时。
- 始终使用约 300ms、ease-out 的滑动动画。下一张由右向左进入，上一张相反；动画期间只保留最后一个新切换意图，前一段结束后再处理，不并行开启第二段。
- 读取、解码和缩放在后台执行，以消息结果交回 UI；不阻塞拖动或动画。当前图显示后预加载下一张，非预加载方向允许短暂等待，但等待时保留当前图，禁止白屏闪烁。
- 允许解码时短暂持有全分辨率数据，随后缩到物理显示需求并释放整图。长期只留当前图与下一张的显示数据，不保存全分辨率历史或大缓存；转场期间允许当前图与目标图同时存在，动画完成后立即释放切走图的纹理与不再需要的数据。
- 暂定保留 image，并以 Limits 拒绝过大输出。普通 1080p、2K、4K 图片必须正常显示；合法但超限的 100MP 级图片允许拒绝。Limits 不是进程工作集硬上限，不以库默认值代替产品安全线。

### 6. 菜单、托盘、关闭与退出

- 相框右键菜单包括：上一张、下一张、播放或暂停；顺序或随机的二选一勾选；六档间隔；适应或填充；打开当前图片、打开所在文件夹、复制图片路径；选择图片文件夹、重新扫描；设置、开机自启和退出。
- 托盘图标常驻，左键单击显示或隐藏相框；右键菜单提供显示或隐藏、播放或暂停、上一张、下一张、设置和退出。菜单状态反映同一份实际生效状态。
- 关闭相框，包括相框上的 Alt+F4，只隐藏相框，进程保留，播放中继续轮播。退出只能由相框菜单或托盘菜单的明确命令结束进程。设置窗关闭不等于相框关闭。
- 系统默认看图器、所在文件夹与剪贴板操作正确处理包含空格和特殊字符的路径，不把原图操作改成导出缩略图。
- 开机自启通过当前用户的 Run 项实现，开关与实际状态保持一致；写入失败时，开关及配置回到写入前状态，不弹窗。除该自启项外，不把业务配置写入注册表。

### 7. 设置窗与配置契约

- 菜单和托盘打开同一块独立、非模态设置窗，已打开时带到前台，无确定或取消。控件仅包括文件夹路径与重新扫描、播放模式、六档间隔与秒数框、适应或填充、开机自启、恢复默认位置与大小、宽高比锁定；设置窗不另设文件夹选择器，选择文件夹走相框菜单。
- 设置窗位于相框所在屏幕中央；相框隐藏或不在任何屏幕上时位于主屏中央。其位置不保存，也不随相框移动。
- 关闭按钮、设置窗的 Alt+F4 和 Esc 只关闭设置窗，不暂停轮播、不退出进程、不隐藏相框。设置窗开着时，相框可独立隐藏；从托盘打开设置窗不唤出已隐藏的相框。
- 开关、单选和预设立即生效并落盘，与菜单同步。路径框与秒数框先去掉首尾空白，在失焦或回车时提交；输入过程中不扫描、不改计时，回车后焦点仍在输入框。
- 点相框或设置窗其他普通控件算失焦并提交；但点击重新扫描只扫描已生效路径、不提交草稿。关闭设置窗时未提交的路径和秒数作废，不能借关闭导致的失焦提交。菜单或预设修改同一项时，也丢弃该项草稿并显示生效值。
- 秒数框仅接受普通十进制整数。空白、小数或解析失败保留上次有效值，不回退 30；可解析但越界的整数在提交时钳制到 3 或 99999999，并显示结果。
- 配置读取与输入框校验分开：配置中的越界整数钳制并写回；小数、损坏或缺失间隔回退 30 并写回。配置可恢复时只修坏字段，保留合法窗口位置与其他合法手改值；不可读的配置必须恢复到合法默认配置，不崩溃。
- 无效、空白、指向文件或不存在的文件夹路径保留输入文本，图库进入空状态，不重复弹窗。递归扫描是固定行为，不提供开关；配置手改按重启生效，不监视配置文件。
- 恢复默认位置与大小为 480×320、当前屏幕右下角内缩 24px，并立即保存。相框隐藏时使用主屏并显示相框；若宽高比锁定开启，锁定比例同步改为 480×320 的比例。
- 保留原有配置分区和已定义设置，新增跨启动的本轮进度与历史；不保存洗牌袋，不在本规格臆定新增字段名称或数据表示。保存当前图片路径、窗口位置与尺寸、锁定开关、文件夹、播放模式、间隔、显示模式和自启状态。
- 新配置仍写入 `pause_on_hover = true`、`animation = "slide"`、`show_filename = false`。这些键的合法手改值只保存，不驱动行为；非法值回退并写回。V1 始终滑动，悬停不暂停，不显示文件名，也不展示这三个设置控件。

## Testing Decisions

### 1. 接缝与测试原则

- 本节接缝已经用户确认：以应用行为入口为主要自动化边界，另保留第 10 节指定的 playlist 核心单测；窗口、解码先独立最小验证，Windows 系统行为实机验收。
- 当前仓库没有应用代码、测试或可复用测试工具。需求已明确要求 playlist 是可单测的纯逻辑模块，这是已有的设计接缝，不得写成已经存在测试实现或先例。
- 应用行为测试通过公开的用户意图、时间推进、加载成功或失败、配置恢复及图库变化，观察成功显示路径、播放状态、计时触发、设置生效和持久化结果。可控制时间、随机性和加载结果以复现行为，但不为每个私有函数另开接缝，不绑定内部容器、算法调用次数、线程调度或 GUI 帧数。
- 测试外部行为和不变量，不做整段随机排列快照，不用真实 sleep 等待长间隔。只在隔离时间、随机性及系统副作用所必需的边界替换依赖；mock 返回成功不算 Windows 能力、资源占用或兼容性通过。
- playlist 按原需求先写测试，再写实现。已有票的手势五条、随机续播十条和设置窗 Decision 是行为用例来源；不是现成测试代码。

### 2. playlist 核心单测

- 顺序模式：完整路径自然序、连续数字、非数字 Unicode 码点、末尾循环、当前路径恢复及缺失后定位。
- 随机模式：一轮 N 张的新选择无重复、至少两张时轮间首尾避让、只剩一张与空图库、失败候选不记账。用不变量断言覆盖不同洗牌结果，不要求某一固定随机顺序。
- 历史：实际成功显示顺序、上一张、跳过缺失路径、回看不修改本轮进度、下一张和轮播先回到最新图、512 条上限及跨启动恢复。
- 续播：恢复当前图可重复显示退出前那张；保存的本轮进度继续防重复；不要求保存洗牌袋；当前图缺失时清空旧进度并开始新一轮；损坏状态字段按缺失处理。
- 图库增删：删除路径剔除、新增路径成为本轮未看、仍有未看旧路径时不整轮重洗、当前有效图不被中断。这里只验证核心在收到新图库后的行为，不由此引入定时重扫或文件监听。

### 3. 应用行为与真实文件边界

- 计时与导航：自动间隔、手动重计、暂停时可手动导航、间隔变更与同值不变、暂停中变更后恢复计满、模式和显示模式不额外重计。
- 手势：系统阈值对应的拖动、侧边延迟单击、双击不切换且固定打开目标、超出双击距离的重新判定、右键取消待定动作及拖动回滚、动画中的最后意图合并。自动化验证判定结果，实机验证系统输入和真实窗口动作。
- 显示提交：预加载不提前记入进度或历史；读取或解码失败跳过；目标未就绪保留当前图；方向正确且没有并行动画；关闭相框与退出命令分离。
- 设置：即时控件同步、输入框草稿与提交、重新扫描例外、关闭丢弃草稿、菜单覆盖草稿、两种间隔校验规则、隐藏时打开设置窗与恢复默认的不同效果、自启失败回滚、三个 P1 键保留但不驱动行为。
- 真实文件测试使用临时目录和小型有效图片，覆盖递归扫描、大小写扩展名、中文及特殊字符路径、空图库、坏图与伪装扩展名、配置默认值及修复、跨启动状态读写、日志包含跳过路径和超限原因。优先通过应用或模块公开入口断言实际产出，不靠 mock 证明能读写文件。

### 4. 正式窗口实现之前的独立最小验证

- 只准备窗口能力验证程序、操作清单和诊断日志，不掺入完整轮播、图片解码、托盘、配置恢复或宽高比锁定。
- 先在当前本机 Windows 11 x64 Build 26100，由用户实际操作，检查无标题栏和系统边框、四边四角反复缩放、120×120 逻辑最小尺寸、内容区拖动、缩放不误触移动、默认不置顶、创建时不抢焦点，并记录 DPI 与物理客户区尺寸。
- 最大化时不发起边缘缩放；恢复普通大小后，内容移动和八方向缩放仍可用。验证这条不增加正式产品的最大化按钮。
- 编译、截图和 API 成功返回均不能替代实际操作。未操作项标为未验证。本机通过只允许继续实现，不等于 Windows 10、混合 DPI 双屏等环境已兼容。

### 5. 正式解码实现之前的独立最小验证

- 用普通 1080p、2K、4K 和 100MP 级图片，以及损坏图、伪装扩展名样本，验证完整解码、缩放、下一张预加载和拒绝路径。记录样本尺寸、窗口逻辑及物理尺寸、显示模式、稳定工作集、瞬时峰值和拒绝原因，不能只报告理论像素字节数。
- 默认 480×320 窗口，解码、缩放及下一张预加载完成后，稳定工作集必须 ≤80MB；普通图片正常显示，超限大图可记录并跳过。连续轮播 1 小时不得持续增长。
- 瞬时峰值单独记录，不自动套用稳定工作集的 80MB，也不能无限上涨。上限为**峰值工作集 ≤192MB**（2026-11-22 用户确认）：推导口径是稳态预算 80MB + 单次解码缓冲上限 `PRODUCT_LIMITS.max_alloc = 96MiB` = 176.7MB，再留 8% 分配器与纹理抖动余量。测点：`Get-Process` 采 `PeakWorkingSet64`，覆盖至少一轮含 100MP 样本的完整轮播；超限即判定失败。解码拒绝阈值沿用 `src/loading.rs:14` 的产品 Limits（12000×12000、96MiB）。
- 最小验证通过不替代最终完整程序中的性能复测。若未达标，先排查重复缓冲、释放时机和限制设置；确认仍无法满足后另开备选票。

| NFR-5 | 长期仅当前图和下一张显示数据；按物理像素需求缩放，填充按覆盖尺寸；完整解码数据及时释放，切换完成释放旧纹理，拒绝限制已确认 |
| 自动化 | `cargo test` 全部通过，覆盖 playlist 的洗牌袋、历史和图库增删，并覆盖本规格的应用行为关键分支 |
| 交付 | 源码、release `MoeFrame.exe`、简短 README 齐备，记录真实验收结果与未验证环境 |

- NFR-6 的后台加载、NFR-7 的异常及大图健壮性、NFR-8 的 10,000 张图库规模仍是实现约束，不能因第 10 节单列 NFR-1～NFR-5 就将它们删除；10,000 张路径扫描和启动应保持可操作，不全量解码。
- 实机证据记录构建、系统版本、显示器和 DPI、图片样本与测量条件，并以任务管理器读数及持续观察核对资源指标。自动化输出、日志和人工检查结果分别记录，不把待确认项预先勾选。
- 窗口最小验证由用户本机操作确认。最终拖动、托盘、自启和任务管理器验收的具体执行人尚未指定；执行到这些项目时须明确责任人，在收到真实结果之前保持未验证，不由 Agent 代填通过。

## Out of Scope

- 悬停条及其按钮、悬停暂停、显示文件名、淡入淡出或无动画、定时重扫、文件系统监听、图库自动热更新、拖放文件夹、avif、单实例。不因原需求某处交叉列举就升格；手动重新扫描及其核心图库增删规则不在此排除项中。
- Stretch、额外圆角或皮肤打磨、宽边框。仅验证最大化后恢复，不新增正式产品最大化按钮。
- 全屏壁纸、动态壁纸、WorkerW、图片编辑或下载、在线图源、账号、同步、联网和遥测、多相框、macOS/Linux 实际适配。
- V2 候选，包括动图播放、视频或 Live2D、收藏快捷操作、标签权重、毛玻璃、按主色调配色。
- 直接更换 GUI 框架或解码器、把库默认限制当作已确认产品阈值、现在预切完整实施票、将原 wayfinder 子票改为 `ready-for-agent`。
- 在本次写规格时实现产品、执行实机验证，或宣称窗口和解码已经通过验收。

### 固定运行位置与说明要求

- 业务配置位于 `%APPDATA%\MoeFrame\config.toml`；坏图跳过日志追加到 `%APPDATA%\MoeFrame\moe_frame.log`。
- 开机自启使用 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中的 `MoeFrame` 项；其他业务配置不写注册表。
- README 须简述首次启动、导航、适应或填充、关闭与退出、托盘、自启、配置和日志位置，并明确三个 P1 键尚未生效、自定义间隔为 3 到 99999999 秒。
- ADR-0003 同时要求实现时补充需求第 6 节配置注释，说明三个 P1 键和新间隔范围；这不是将原 FR-401/FR-504 改成另一份需求。本次仅发布规格，不改动需求原文。

### 尚未完成的验收门禁

1. 窗口验证程序、用户操作和结果记录尚未完成；Windows 10 与混合 DPI 双屏等环境未获通过证据。
2. 解码最小验证尚未完成，没有普通图片或超大图的实测内存通过结果。
3. 解码瞬时峰值上限：**≤192MB 工作集**，2026-11-22 由用户确认（推导见解码门禁条）。解码拒绝阈值沿用产品 Limits（12000×12000、96MiB，`src/loading.rs:14`）。
4. 最终需要人工执行的验收项目，具体执行人仍待落实；未执行项目保持未验证。

本规格允许开始有明确范围的验证工作，不代表这些缺口已经关闭，也不降低最终 release 完成线。
