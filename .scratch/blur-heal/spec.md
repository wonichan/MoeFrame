# 失焦切换偶现模糊：诊断与修复

## 症状（用户 2026-11-22 报告）

失去焦点时，偶现定时切换后的插图模糊；点击选中程序后立即恢复清晰。

## 诊断结论（diagnosing-bugs 流程）

机制链（代码实证 + 管线级模拟复现）：

1. 导航解码口径在 `begin_load` 时快照为当时窗口物理尺寸（旧图口径）；
   切到更宽的图后窗口随比例变宽，纹理相对新窗口偏小 → 放大显示即糊。
   这是既定设计，靠管线 `tick` 的「治愈刷新」纠正。
2. 治愈刷新有 0.25s 停稳门（防拖动缩放反复解码），计时走的是 egui
   帧时间；而切换完成后帧尾调度直接睡到下一次轮播截止，不再出帧 →
   停稳永远走不完，刷新不发。聚焦产生新帧后计时瞬间走完 → 立即变
   清晰。与症状逐字吻合；「偶现」 = 只有切到更宽比例（窗口变大）
   时纹理才小于显示面积。
3. 管线级模拟（喂入失焦切换的帧序列）证实：转正后的稀疏帧内无刷
   新发出，迟到 30s 的焦点帧才触发刷新。

## 修复

宿主帧尾调度加「治愈保活」：`refresh_display_data` 观测到当前口径
过期且目标是新出现的变化时，给帧尾设 2s 保活截止，期间按 50ms
唤醒——停稳计时与刷新回送不再依赖外部唤醒。同一目标只续一次，
刷新失败也不会无限保活。调度裁决抽为纯函数 `next_frame_delay`
并加回归测试。管线与解码口径不动。

## 与既有事项的关系

- 与搁置的「原生 resize 偶现异常」可能同源或相邻：若 resize 本身
  迟到，保活帧也给它 2s 的落地窗口；仍不落地则维持原行为（聚焦
  后恢复），不在本票处理。
